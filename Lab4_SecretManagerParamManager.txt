   └─ Next

Lab 17.2: Retrieve Secret via CLI
Open CloudShell:
bash# List all secrets
aws secretsmanager list-secrets

# Get specific secret value
aws secretsmanager get-secret-value \
  --secret-id prod/database/mysql/credentials

# Output shows:
{
  "ARN": "arn:aws:secretsmanager:us-east-1:...",
  "Name": "prod/database/mysql/credentials",
  "VersionId": "...",
  "SecretString": "{\"username\":\"admin\",\"password\":\"xyz123...\"}",
  "CreatedDate": "2026-02-13..."
}

# Extract just the password
aws secretsmanager get-secret-value \
  --secret-id prod/database/mysql/credentials \
  --query SecretString \
  --output text

# Output: {"username":"admin","password":"xyz123..."}

Lab 17.3: Create Different Types of Secrets
bash# Secret for API key (plain text)
aws secretsmanager create-secret \
  --name prod/api/stripe-key \
  --description "Stripe API key for production" \
  --secret-string "sk_live_abc123xyz..."

# Secret for SSH private key
aws secretsmanager create-secret \
  --name prod/ssh/deploy-key \
  --description "SSH key for deployment" \
  --secret-string file://~/.ssh/id_rsa

# Secret for JSON config
aws secretsmanager create-secret \
  --name prod/app/config \
  --description "Application configuration" \
  --secret-string '{
    "database_host": "mydb.example.com",
    "cache_host": "redis.example.com",
    "api_key": "secret123"
  }'

Lab 17.4: Update Secret (Create New Version)
bash# Update password
aws secretsmanager update-secret \
  --secret-id prod/database/mysql/credentials \
  --secret-string '{
    "username": "admin",
    "password": "newPassword456!"
  }'

# List versions
aws secretsmanager list-secret-version-ids \
  --secret-id prod/database/mysql/credentials

# Output shows:
{
  "Versions": [
    {
      "VersionId": "abc123...",
      "VersionStages": ["AWSCURRENT"],  ← Current version
      "CreatedDate": "2026-02-13..."
    },
    {
      "VersionId": "xyz789...",
      "VersionStages": ["AWSPREVIOUS"],  ← Previous version
      "CreatedDate": "2026-02-13..."
    }
  ]
}

# Get previous version
aws secretsmanager get-secret-value \
  --secret-id prod/database/mysql/credentials \
  --version-stage AWSPREVIOUS

Lab 17.5: Delete and Recover Secret
bash# Schedule deletion (7-30 day waiting period)
aws secretsmanager delete-secret \
  --secret-id prod/api/stripe-key \
  --recovery-window-in-days 7

# Output:
{
  "ARN": "...",
  "Name": "prod/api/stripe-key",
  "DeletionDate": "2026-02-20..."  ← 7 days from now
}

# Cancel deletion (within recovery window)
aws secretsmanager restore-secret \
  --secret-id prod/api/stripe-key

# Output:
{
  "ARN": "...",
  "Name": "prod/api/stripe-key"
}

✅ Secret restored!

Lab 17.6: Access Secret from EC2
bash# SSH into your EC2
ssh -i aws-security-key.pem ec2-user@YOUR_EC2_IP

# Install jq (JSON parser)
sudo yum install -y jq

# Retrieve secret
aws secretsmanager get-secret-value \
  --secret-id prod/database/mysql/credentials \
  --region us-east-1 \
  --query SecretString \
  --output text | jq -r '.password'

# Output: xyz123... (just the password)

# Use in a script
DB_PASSWORD=$(aws secretsmanager get-secret-value \
  --secret-id prod/database/mysql/credentials \
  --query SecretString \
  --output text | jq -r '.password')

echo "Connecting to database with password: $DB_PASSWORD"

# In real app:
# mysql -u admin -p"$DB_PASSWORD" -h mydb.example.com

Lab 17.7: Audit Secret Access (CloudTrail)

  --lookup-attributes AttributeKey=EventName,AttributeValue=GetSecretValue \
  --max-results 10

# Shows:
# - Who retrieved the secret
# - When
# - From where (IP)
# - Which secret

Lab 18.2: Create Parameter Hierarchy
bash# CloudShell

# Dev environment parameters
aws ssm put-parameter \
  --name /myapp/dev/database/host \
  --type String \
  --value "dev-db.example.com"

aws ssm put-parameter \
  --name /myapp/dev/database/port \
  --type String \
  --value "3306"

aws ssm put-parameter \
  --name /myapp/dev/database/password \
  --type SecureString \
  --value "dev-password-123"

# Prod environment parameters
aws ssm put-parameter \
  --name /myapp/prod/database/host \
  --type String \
  --value "prod-db.example.com"

aws ssm put-parameter \
  --name /myapp/prod/database/port \
  --type String \
  --value "3306"

aws ssm put-parameter \
  --name /myapp/prod/database/password \
  --type SecureString \
  --value "prod-password-xyz"

✅ Hierarchy created:
/myapp/
├── dev/
│   └── database/
│       ├── host
│       ├── port
│       └── password
└── prod/
    └── database/
        ├── host
        ├── port
        └── password

# **COMPARISON TABLE - FILL THIS OUT:**

| Feature | Secrets Manager | Parameter Store |
|---------|----------------|-----------------|
| **Cost** | $0.40/secret/month + $0.05/10K API calls | FREE (Standard), $0.05/advanced/month |
| **Rotation** | ✅ Automatic (built-in) | ❌ Manual (use Lambda) |
| **Secret size** | 65,536 bytes (~64 KB) | Standard: 4 KB, Advanced: 8 KB |
| **Versioning** | ✅ Automatic | ✅ Up to 100 versions |
| **Cross-region** | ✅ Can replicate | ❌ Regional only |
| **RDS integration** | ✅ Native | ❌ Manual |
| **Hierarchy** | ❌ No | ✅ Yes (paths) |
| **Use case** | Database passwords, API keys | App config, non-sensitive data |

# **WHEN TO USE WHAT?**

## **Use Secrets Manager:**
- ✅ Database credentials (RDS, Redshift, DocumentDB)
- ✅ Need automatic rotation
- ✅ API keys that change frequently
- ✅ Cross-region replication needed
- ✅ Budget allows ($0.40/month per secret OK)

## **Use Parameter Store:**
- ✅ Application configuration
- ✅ Non-sensitive data (app name, URLs)
- ✅ Encrypted secrets with manual rotation OK
- ✅ Hierarchical organization needed
- ✅ Cost-sensitive (FREE for standard)
- ✅ Many parameters (100s to 1000s)

## **Use Both:**
- Secrets Manager: Database passwords
- Parameter Store: App config, feature flags
- Best of both worlds!
