## **Service 1: CloudTrail - "What Happened?"**

### **Core Concept:**
```
CloudTrail = Complete audit trail of every API call

What it logs:
├─ Who: UserIdentity (IAM user, role, root)
├─ What: EventName (CreateBucket, PutObject, etc.)
├─ When: EventTime (precise timestamp)
├─ Where: SourceIPAddress + Region
├─ Result: Success or error
└─ Details: Full request/response parameters

Use cases:
✅ Security investigation (who deleted my bucket?)
✅ Compliance audit trail (prove what happened)
✅ Troubleshooting (why did API call fail?)
✅ Anomaly detection (unusual activity patterns)
```

### **Key Features You Built:**
```
✅ Trail: security-audit-trail
✅ S3 bucket: cloudtrail-logs-pradeep-2026
✅ CloudWatch integration (8 metric filters)
✅ Athena queries for analysis
✅ SNS alerts: SecurityAlerts topic
✅ Log file validation (tamper-proof)

Metric filters created:
1. Root account usage
2. Failed console logins
3. Unauthorized API calls
4. S3 bucket changes
5. IAM policy changes
6. Security group changes
7. Network ACL changes
8. KMS key changes
```

### **Exam Tips:**
```
Q: How to track ALL API calls in AWS account?
A: Enable CloudTrail

Q: How to prevent CloudTrail log tampering?
A: Enable log file validation

Q: How to search CloudTrail logs efficiently?
A: Use Amazon Athena (SQL queries)

Q: How to get real-time alerts from CloudTrail?
A: CloudTrail → CloudWatch Logs → Metric Filters → Alarms

Q: Does CloudTrail log data events by default?
A: NO - only management events. Must enable data events separately.
```

## **Service 2: GuardDuty - "Is It Malicious?"**

### **Core Concept:**
```
GuardDuty = AI-powered threat detection

Data sources (automatic):
├─ CloudTrail event logs
├─ VPC Flow Logs
├─ DNS logs
├─ EKS audit logs (optional)
├─ RDS login activity (optional)
└─ Lambda network activity (optional)

Machine Learning analyzes for:
├─ Compromised instances (crypto mining, backdoors)
├─ Stolen credentials (Tor usage, unusual locations)
├─ Reconnaissance (port scanning, enumeration)
├─ Data exfiltration (unusual data transfer)
└─ 100+ threat types

Key: NO agents, NO configuration needed!
```

### **Threat Categories You Learned:**
```
1. Backdoor - C&C communication
2. Behavior - Unusual API calls
3. CryptoCurrency - Mining detected (HIGH $$$ impact!)
4. PenTest - Kali Linux, scanning tools
5. Policy - Security controls disabled
6. PrivilegeEscalation - Attacker gaining access
7. Recon - Port scanning, enumeration
8. ResourceConsumption - Launching expensive instances
9. Stealth - Covering tracks, deleting logs
10. Trojan - Malware detected
11. UnauthorizedAccess - Stolen credentials, Tor
12. Impact - Data exfiltration

Severity: 0.1 (Low) to 8.9+ (Critical)
```

### **What You Built:**
```
✅ Enabled GuardDuty (1-click!)
✅ Generated 50+ sample findings
✅ Created SNS email alerts
✅ Built Lambda auto-isolation function
✅ EventBridge rule for automated response

Auto-response workflow:
GuardDuty finding (severity ≥7.0)
→ EventBridge
→ Lambda (IsolateCompromisedInstance)
→ Changes security group to isolation-sg
→ SNS notification
→ Instance quarantined in seconds! 🔒
```

### **Exam Tips:**
```
Q: Real-time threat detection in AWS?
A: Amazon GuardDuty

Q: Does GuardDuty require agents on EC2?
A: NO - completely agentless

Q: How to automate response to GuardDuty findings?
A: EventBridge + Lambda

Q: GuardDuty vs Inspector - what's the difference?
A: GuardDuty = Runtime threats (active attacks)
   Inspector = Vulnerabilities (CVEs, misconfigurations)

Q: Cost of GuardDuty?
A: ~$4-10/month per account + usage
```

## **Service 3: Macie - "Where's Sensitive Data?"**

### **Core Concept:**
```
Macie = AI-powered sensitive data discovery in S3

What it finds:
├─ PII: SSN, driver's license, passport, names
├─ PHI: Medical records, insurance IDs
├─ Financial: Credit cards, bank accounts
├─ Credentials: AWS keys, API keys, passwords
├─ 100+ managed data identifiers
└─ Custom identifiers (your regex patterns)

How it works:
1. Scans S3 bucket contents (not just metadata!)
2. Uses ML to identify sensitive data
3. Creates findings with exact locations
4. Maps to compliance standards
5. Alerts via EventBridge
```

### **What You Found:**

```
Test data scanned:
```

## **Service 4: Inspector - "What's Vulnerable?"**

### **Core Concept:**
```
Inspector = Automated vulnerability scanner

What it scans:
├─ EC2 instances (OS packages, network)
├─ ECR container images (all layers)
├─ Lambda functions (runtime, dependencies)

What it finds:
├─ CVEs (Common Vulnerabilities and Exposures)
├─ Package vulnerabilities
├─ Network misconfigurations (0.0.0.0/0)
├─ Software outdated versions
└─ Missing security patches

CVSS Scoring:
├─ Critical: 9.0-10.0 (patch immediately!)
├─ High: 7.0-8.9 (patch within 7 days)
├─ Medium: 4.0-6.9 (patch within 30 days)
└─ Low: 0.1-3.9 (patch when convenient)
```
