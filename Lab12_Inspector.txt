PART 1: WHAT IS AWS INSPECTOR? (15 MIN)
The Problem:
Your infrastructure has vulnerabilities:
├─ EC2 instances with outdated software
├─ Container images with known CVEs
├─ Lambda functions with vulnerable dependencies
├─ Network misconfigurations
└─ Missing security patches

Attackers exploit these vulnerabilities:
├─ Remote code execution (RCE)
├─ Privilege escalation
├─ Data exfiltration
├─ Denial of service
└─ Complete system compromise

Manual scanning: Time-consuming, error-prone, outdated quickly
The Solution: AWS Inspector
AWS Inspector = Automated vulnerability scanner 🔍

What it does:
✅ Continuously scans EC2, ECR, Lambda
✅ Finds CVEs (Common Vulnerabilities and Exposures)
✅ Finds package vulnerabilities
✅ Finds network exposure issues
✅ Provides severity scores (CVSS)
✅ Gives remediation guidance
✅ Integrates with Security Hub
✅ Runs automatically (no agents needed!)

It's like having a security researcher scanning 24/7!

CVE Severity Scores (CVSS):
CVSS = Common Vulnerability Scoring System (0.0 - 10.0)

None: 0.0
└─ No vulnerability

Low: 0.1 - 3.9 🟢
├─ Minor impact
├─ Example: Information disclosure
└─ Remediate: When convenient

Medium: 4.0 - 6.9 🟡
├─ Moderate impact
├─ Example: Denial of service
└─ Remediate: Within 30 days

High: 7.0 - 8.9 🟠
├─ Significant impact
├─ Example: Remote code execution (with auth)
└─ Remediate: Within 7 days

Critical: 9.0 - 10.0 🔴
├─ Severe impact
├─ Example: Unauthenticated RCE
└─ Remediate: IMMEDIATELY (same day)

Inspector uses CVSS v3.1 scoring

Finding Types:
1. Package Vulnerability:
Finding: CVE-2023-1234 in OpenSSL

Details:
├─ CVE ID: CVE-2023-1234
├─ CVSS Score: 9.8 (Critical) 🔴
├─ Package: openssl
├─ Installed version: 1.1.1k
├─ Fixed version: 1.1.1u
├─ Affected resource: i-abc123...
├─ First seen: 2026-03-03 10:00:00
└─ Status: ACTIVE

Description:
"Remote attackers can execute arbitrary code via
crafted SSL/TLS handshake"

Remediation:
1. Update OpenSSL: sudo yum update openssl
2. Reboot instance if kernel updated
3. Verify patch: openssl version
4. Expected: OpenSSL 1.1.1u or later

References:
├─ https://nvd.nist.gov/vuln/detail/CVE-2023-1234
├─ https://www.openssl.org/news/secadv/...
└─ https://access.redhat.com/security/cve/...

2. Network Reachability:
Finding: Network path allows broad access

Details:
├─ Type: Network Reachability
├─ Severity: Medium 🟡
├─ Instance: i-abc123...
├─ Port: 22 (SSH)
├─ Protocol: TCP
├─ Security Group: sg-xyz789
└─ Issue: Allows 0.0.0.0/0 (entire internet)

Risk:
"SSH port exposed to the internet increases
attack surface for brute force attempts"

Remediation:
1. Restrict security group to known IPs only
2. Or use Systems Manager Session Manager
3. Or use bastion host with strict access
4. Enable MFA for SSH if keeping open

Impact:
├─ Brute force attacks
├─ Credential stuffing
├─ Potential unauthorized access
└─ Compliance violations (CIS Benchmark)

Lab 62.2: Create Suppression Rule via CLI
bash# CloudShell

# Create suppression rule
aws inspector2 create-filter \\
  --name "Suppress-Accepted-Risks" \\
  --description "Findings accepted as business risk" \\
  --action SUPPRESS \\
  --filter-criteria '{
    "severity": [{"comparison": "EQUALS", "value": "LOW"}],
    "findingType": [{"comparison": "EQUALS", "value": "NETWORK_REACHABILITY"}]
  }'

# List suppression rules
aws inspector2 list-filters \\
  --action SUPPRESS

# Update rule
aws inspector2 update-filter \\
  --filter-arn "arn:aws:inspector2:..." \\
  --action SUPPRESS
