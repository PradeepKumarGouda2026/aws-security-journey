## **What We're Building:**

## **Lab 74.1: Create VPC**

```bash
# CloudShell

echo "=== Creating Secure VPC Architecture ==="

# Create VPC
VPC_ID=$(aws ec2 create-vpc --cidr-block 10.0.0.0/16 --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=Production-VPC}]' --query 'Vpc.VpcId' --output text)

echo "VPC created: $VPC_ID"

# Enable DNS hostnames (needed for public IPs)
aws ec2 modify-vpc-attribute --vpc-id $VPC_ID --enable-dns-hostnames

echo "✅ VPC configured with DNS hostnames"
```

## **Lab 74.2: Create Subnets (3-Tier Architecture)**

```bash
# CloudShell

echo "=== Creating Subnets ==="

# Public Subnet (Web Tier)
PUBLIC_SUBNET=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.1.0/24 --availability-zone us-east-1a --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Public-Web-Subnet}]' --query 'Subnet.SubnetId' --output text)

echo "Public subnet created: $PUBLIC_SUBNET"

# Private Subnet 1 (App Tier)
PRIVATE_SUBNET_1=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.2.0/24 --availability-zone us-east-1a --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Private-App-Subnet}]' --query 'Subnet.SubnetId' --output text)

echo "Private app subnet created: $PRIVATE_SUBNET_1"

# Private Subnet 2 (Database Tier)
PRIVATE_SUBNET_2=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.3.0/24 --availability-zone us-east-1a --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Private-DB-Subnet}]' --query 'Subnet.SubnetId' --output text)

echo "Private DB subnet created: $PRIVATE_SUBNET_2"

# Enable auto-assign public IP on public subnet
aws ec2 modify-subnet-attribute --subnet-id $PUBLIC_SUBNET --map-public-ip-on-launch

echo "✅ All subnets created!"
echo "  Public (Web): $PUBLIC_SUBNET"
echo "  Private (App): $PRIVATE_SUBNET_1"
echo "  Private (DB): $PRIVATE_SUBNET_2"
```

## **Lab 74.5: Create Route Tables**

# **LAB 75: IMPLEMENT SECURITY GROUPS (TIER ISOLATION)**

## **Lab 75.1: Create Web Tier Security Group**

```bash
# CloudShell

echo "=== Creating Security Groups ==="

# Web Tier Security Group
WEB_SG=$(aws ec2 create-security-group --group-name web-tier-sg --description "Web tier security group" --vpc-id $VPC_ID --tag-specifications 'ResourceType=security-group,Tags=[{Key=Name,Value=Web-Tier-SG}]' --query 'GroupId' --output text)

echo "Web SG created: $WEB_SG"

# Allow HTTP from internet
aws ec2 authorize-security-group-ingress --group-id $WEB_SG --protocol tcp --port 80 --cidr 0.0.0.0/0

# Allow HTTPS from internet
aws ec2 authorize-security-group-ingress --group-id $WEB_SG --protocol tcp --port 443 --cidr 0.0.0.0/0

# Allow SSH from your IP only (replace with your IP!)
MY_IP=$(curl -s https://checkip.amazonaws.com)
aws ec2 authorize-security-group-ingress --group-id $WEB_SG --protocol tcp --port 22 --cidr $MY_IP/32

echo "✅ Web tier security group configured"
echo "   - HTTP/HTTPS: Open to internet"
echo "   - SSH: Only from $MY_IP"
```

# **LAB 76: CONFIGURE VPC ENDPOINTS (PRIVATE AWS ACCESS) 🔒**

Let's add VPC Endpoints so your private instances can access AWS services WITHOUT going through the internet!

---

## **Why VPC Endpoints Matter:**

```
WITHOUT VPC Endpoint:
Private EC2 → NAT Gateway → Internet Gateway → Internet → S3
├─ Traffic goes through internet (less secure)
├─ Costs money (NAT Gateway data processing)
├─ Higher latency
└─ Internet dependency ❌

WITH VPC Endpoint:
Private EC2 → VPC Endpoint → S3 (direct, private connection)
├─ Traffic stays within AWS network ✅
├─ FREE (for Gateway Endpoints) ✅
├─ Lower latency ✅
└─ More secure ✅
```

---

## **Lab 76.1: Create S3 Gateway Endpoint (FREE!)**

```bash
# CloudShell

# Create S3 Gateway Endpoint

echo "S3 Gateway Endpoint created: $S3_ENDPOINT"
echo "✅ Private subnets can now access S3 directly (no NAT Gateway needed)!"
```

# **LAB 77: CONFIGURE NETWORK ACLs (SUBNET FIREWALL) 🛡️**

Network ACLs = Additional layer of defense at the subnet level!

---

## **Lab 77.1: Create Custom NACL for Public Subnet**

```bash
# CloudShell

echo "=== Creating Network ACLs ==="

# Create NACL for Public Subnet
PUBLIC_NACL=$(aws ec2 create-network-acl --vpc-id $VPC_ID --tag-specifications 'ResourceType=network-acl,Tags=[{Key=Name,Value=Public-NACL}]' --query 'NetworkAcl.NetworkAclId' --output text)

echo "Public NACL created: $PUBLIC_NACL"

# INBOUND RULES

# Rule 100: Allow HTTP from internet
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 100 --protocol tcp --port-range From=80,To=80 --cidr-block 0.0.0.0/0 --rule-action allow --ingress

# Rule 110: Allow HTTPS from internet
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 110 --protocol tcp --port-range From=443,To=443 --cidr-block 0.0.0.0/0 --rule-action allow --ingress

# Rule 120: Allow SSH from your IP only
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 120 --protocol tcp --port-range From=22,To=22 --cidr-block $MY_IP/32 --rule-action allow --ingress

# Rule 130: Allow ephemeral ports (return traffic)
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 130 --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --ingress

# Rule 140: Allow traffic from private subnets
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 140 --protocol -1 --cidr-block 10.0.0.0/16 --rule-action allow --ingress

echo "✅ Public NACL inbound rules created"

# OUTBOUND RULES

# Rule 100: Allow HTTP to internet
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 100 --protocol tcp --port-range From=80,To=80 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 110: Allow HTTPS to internet
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 110 --protocol tcp --port-range From=443,To=443 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 120: Allow ephemeral ports (return traffic)
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 120 --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 130: Allow all to private subnets
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 130 --protocol -1 --cidr-block 10.0.0.0/16 --rule-action allow --egress

echo "✅ Public NACL outbound rules created"

# Associate with public subnet
aws ec2 replace-network-acl-association --association-id $(aws ec2 describe-network-acls --filters "Name=association.subnet-id,Values=$PUBLIC_SUBNET" --query 'NetworkAcls[0].Associations[0].NetworkAclAssociationId' --output text) --network-acl-id $PUBLIC_NACL

echo "✅ Public NACL associated with public subnet"
```

## **Lab 77.2: Create Custom NACL for Private Subnets**

```bash
# CloudShell

echo "=== Creating Private NACL ==="

# Create NACL for Private Subnets
PRIVATE_NACL=$(aws ec2 create-network-acl --vpc-id $VPC_ID --tag-specifications 'ResourceType=network-acl,Tags=[{Key=Name,Value=Private-NACL}]' --query 'NetworkAcl.NetworkAclId' --output text)

echo "Private NACL created: $PRIVATE_NACL"

# INBOUND RULES

# Rule 100: Allow traffic from VPC (inter-subnet communication)
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 100 --protocol -1 --cidr-block 10.0.0.0/16 --rule-action allow --ingress

# Rule 110: Allow ephemeral ports from internet (for NAT Gateway return traffic)
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 110 --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --ingress

echo "✅ Private NACL inbound rules created"

# OUTBOUND RULES

# Rule 100: Allow all to VPC
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 100 --protocol -1 --cidr-block 10.0.0.0/16 --rule-action allow --egress

# Rule 110: Allow HTTP to internet (for updates)
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 110 --protocol tcp --port-range From=80,To=80 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 120: Allow HTTPS to internet
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 120 --protocol tcp --port-range From=443,To=443 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 130: Allow ephemeral ports to internet (for return traffic)
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 130 --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --egress

echo "✅ Private NACL outbound rules created"

# Associate with private subnets
ASSOC_1=$(aws ec2 describe-network-acls --filters "Name=association.subnet-id,Values=$PRIVATE_SUBNET_1" --query 'NetworkAcls[0].Associations[0].NetworkAclAssociationId' --output text)
ASSOC_2=$(aws ec2 describe-network-acls --filters "Name=association.subnet-id,Values=$PRIVATE_SUBNET_2" --query 'NetworkAcls[0].Associations[0].NetworkAclAssociationId' --output text)

aws ec2 replace-network-acl-association --association-id $ASSOC_1 --network-acl-id $PRIVATE_NACL
aws ec2 replace-network-acl-association --association-id $ASSOC_2 --network-acl-id $PRIVATE_NACL

echo "✅ Private NACL associated with private subnets"

echo ""
echo "=== Network ACLs Complete! ==="
echo "Public NACL: $PUBLIC_NACL"
echo "Private NACL: $PRIVATE_NACL"
```

# **EXCELLENT QUESTION! 🎯**

---

## **WHY NO ROUTE TABLE FOR EC2 ENDPOINT:**

### **Gateway Endpoints vs Interface Endpoints**

```
┌─────────────────────────────────────────────────┐
│         GATEWAY ENDPOINTS                        │
│  (S3, DynamoDB)                                 │
├─────────────────────────────────────────────────┤
│  How they work:                                 │
│  ├─ Add route to ROUTE TABLE                   │
│  ├─ No IP address                              │
│  ├─ No ENI (Elastic Network Interface)        │
│  └─ Traffic routed via prefix list             │
│                                                 │
│  Route table entry looks like:                 │
│  Destination: pl-xxxxx (S3 prefix list)        │
│  Target: vpce-xxxxx (gateway endpoint)         │
│                                                 │
│  Cost: FREE! ✅                                 │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│         INTERFACE ENDPOINTS                      │
│  (EC2, SNS, SQS, most AWS services)            │
├─────────────────────────────────────────────────┤
│  How they work:                                 │
│  ├─ Create ENI with PRIVATE IP in your subnet │
│  ├─ Uses DNS resolution                        │
│  ├─ No route table changes needed!            │
│  └─ Traffic goes to private IP via DNS        │
│                                                 │
│  Access method:                                │
│  ├─ AWS service DNS name resolves to private IP│
│  ├─ Example: ec2.us-east-1.amazonaws.com      │
│  │   → Resolves to 10.0.2.15 (endpoint ENI)   │
│  └─ Application code unchanged!                │
│                                                 │
│  Cost: ~$7/month per endpoint 💰                │
└─────────────────────────────────────────────────┘
```

---

## **DETAILED EXPLANATION:**

### **Gateway Endpoints (S3, DynamoDB):**

```
How traffic flows:

EC2 in Private Subnet wants to access S3:
├─ EC2: "I need to reach s3.amazonaws.com"
├─ Route table checked:
│   └─ Destination: pl-63a5400a (S3 prefix list)
│       Target: vpce-abc123 (S3 Gateway Endpoint)
├─ Traffic sent to Gateway Endpoint
└─ Gateway Endpoint routes to S3 privately ✅

Route table shows:
Destination         Target
10.0.0.0/16        local
0.0.0.0/0          nat-xxxxx
pl-63a5400a        vpce-abc123 (S3 endpoint)
pl-78a54011        vpce-def456 (DynamoDB endpoint)

This is why we specified --route-table-ids when creating!
```

---

### **Interface Endpoints (EC2, SNS, etc.):**

```
How traffic flows:

EC2 in Private Subnet wants to call EC2 API:
├─ EC2: "I need to call ec2.us-east-1.amazonaws.com"
├─ DNS resolution happens:
│   └─ ec2.us-east-1.amazonaws.com 
│       → Resolves to 10.0.2.15 (endpoint ENI private IP)
├─ Traffic sent to 10.0.2.15 (like any other private IP)
├─ No special routing needed!
└─ Endpoint ENI forwards to EC2 service ✅

Route table shows:
Destination         Target
10.0.0.0/16        local (this includes 10.0.2.15!)
0.0.0.0/0          nat-xxxxx

The endpoint IP is within VPC CIDR, so "local" route handles it!
NO special route needed!
```

## **WHY THE DIFFERENCE?**

```
Gateway Endpoints (older technology):
├─ AWS special routing mechanism
├─ Only works for S3 and DynamoDB
├─ Requires route table modification
├─ Very efficient (no ENI overhead)
└─ FREE! ✅

Interface Endpoints (PrivateLink):
├─ Modern AWS PrivateLink technology
├─ Works for ALL AWS services
├─ Uses standard VPC networking (ENI)
├─ DNS-based (easier to use)
├─ No route table changes needed
├─ Can be accessed from on-premises (VPN/Direct Connect)
└─ Costs money (~$7/month) 💰

AWS kept both because:
- Gateway endpoints are FREE for S3/DynamoDB
- Interface endpoints enable all other services
```

## **EXAM TIP:**

```
Q: How do Gateway Endpoints differ from Interface Endpoints?

A: 
Gateway Endpoints:
- Only S3 and DynamoDB
- Use route table entries
- FREE
- No IP address/ENI

Interface Endpoints:
- All other AWS services
- Use DNS resolution
- Create ENI with private IP
- ~$7/month per endpoint
- No route table modification needed

Remember: "Gateway = Route, Interface = IP"
```

```
Your question revealed the KEY difference:

Both achieve the same goal:

But use different mechanisms:
- Gateway: Routing-based (S3, DynamoDB only)
- Interface: DNS-based (everything else)
```
