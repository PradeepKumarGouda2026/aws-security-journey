## **LAB 41: CREATE CLOUDTRAIL TRAIL**

### **Understanding Trail Types:**

```
Organization Trail:
- Logs ALL accounts in AWS Organization
- Centralized logging
- Best for enterprises

Single Account Trail:
- Logs one AWS account only
- Good for learning/small setups

Multi-Region Trail:
- Logs all regions
- Recommended (default)
- Single trail covers everything

Single-Region Trail:
- Logs one region only
- Legacy, not recommended
```

### **Lab 42.3: Understand Event Structure**

Download an event and examine the JSON:

```json
{
  "Records": [
    {
      "eventVersion": "1.08",
      "userIdentity": {
        "type": "IAMUser",
        "principalId": "AIDAI...",
        "arn": "arn:aws:iam::160326772135:user/alice",
        "accountId": "160326772135",
        "userName": "alice"
      },
      "eventTime": "2026-02-18T14:30:00Z",
      "eventSource": "s3.amazonaws.com",
      "eventName": "CreateBucket",
      "awsRegion": "us-east-1",
      "sourceIPAddress": "203.0.113.45",
      "userAgent": "aws-cli/2.x",
      "requestParameters": {
        "bucketName": "my-new-bucket",
        "CreateBucketConfiguration": {
          "LocationConstraint": "us-east-1"
        }
      },
      "responseElements": null,
      "requestID": "ABC123...",
      "eventID": "xyz789...",
      "readOnly": false,
      "eventType": "AwsApiCall",
      "managementEvent": true,
      "recipientAccountId": "160326772135",
      "eventCategory": "Management"
    }
  ]
}
```

**Key fields to know:**

```
userIdentity:
- type: IAMUser, AssumedRole, Root, AWSService
- userName: alice, bob, Root
- arn: Full ARN of the identity

eventTime: UTC timestamp

eventName: API call (CreateBucket, DeleteObject, etc.)

sourceIPAddress: Where request came from
- IP address for users
- AWS service name for service calls

requestParameters: What was in the request

responseElements: What AWS returned

errorCode: If call failed (AccessDenied, etc.)

readOnly: true = read, false = write/delete

eventType:
- AwsApiCall: Normal API call
- AwsServiceEvent: AWS internal event
- AwsConsoleSignIn: Console login

managementEvent vs dataEvent:
- Management: Control plane (CreateBucket)
- Data: Data plane (PutObject, GetObject)
```

## **LAB 43: CLOUDTRAIL INSIGHTS**

### **What are Insights?**

```
CloudTrail Insights = AI anomaly detection

Detects unusual API activity:
- Spike in failed API calls
- Unusual number of EC2 terminations
- Surge in IAM permission changes
- Abnormal S3 delete operations

How it works:
1. CloudTrail learns normal baseline (7 days)
2. Detects deviations from baseline
3. Generates Insight event
4. Sends alert

Cost: $0.35 per 100,000 write events analyzed
```

## **LAB 44: LOG FILE VALIDATION**

### **What is Log File Validation?**

```
Problem: Attacker deletes CloudTrail logs to hide tracks

Solution: Log file validation
- CloudTrail creates digest files
- Digest = cryptographic hash of logs
- Stored separately
- Cannot modify logs without detection
- Proves logs haven't been tampered with

Digest files:
- Created every hour
- Hash of all log files from that hour
- Chain of hashes (like blockchain!)
- Cannot be altered without detection
```

---

### **Lab 44.1: Enable Validation (Already Enabled)**

```
We enabled this in Lab 41!

To verify:
CloudTrail → Trails → security-audit-trail

Log file validation: ✅ Enabled

S3 bucket structure now includes:
AWSLogs/ACCOUNT/CloudTrail/REGION/YYYY/MM/DD/
├── log.json.gz (actual logs)
└── digest/ (validation files)

Digest files:
ACCOUNT_CloudTrail-Digest_REGION_YYYYMMDD_HASH.json.gz
```

---

### **Lab 44.2: Validate Log Files**

```bash
# Install CloudTrail log validation tool
# (AWS provides Python script)

# Download validation script
wget https://s3.amazonaws.com/cloudtrail-digest-validator/cloudtrail-digest-validator.zip
unzip cloudtrail-digest-validator.zip
cd cloudtrail-digest-validator

# Validate logs
python cloudtrail_digest_validator.py \
  --trail-arn arn:aws:cloudtrail:us-east-1:ACCOUNT:trail/security-audit-trail \
  --start-time 2026-02-18T00:00:00Z \
  --end-time 2026-02-18T23:59:59Z

# Output:
✅ All log files validated successfully
✅ No tampering detected
✅ Chain of custody intact

# If logs were modified:
❌ Validation failed!
❌ Hash mismatch detected
❌ Log files may have been tampered with
🚨 Security incident!
```
