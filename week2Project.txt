## **Component Descriptions:**

```markdown
### 1. S3 Upload Bucket
**Purpose:** Secure storage for customer order files
**Security Controls:**
- Encryption: SSE-KMS with customer-managed key
- Access: Block Public Access enabled (account + bucket)
- Versioning: Enabled (data protection)
- Bucket Policy: Deny unencrypted uploads
- Lifecycle: Move to Glacier after 90 days
- Event Notification: Trigger Lambda on upload

### 2. Lambda Processor
**Purpose:** Process uploaded files and write to database
**Security Controls:**
- IAM Role: Least privilege (S3 read, Secrets read, RDS connect)
- VPC: Runs in private subnet (no internet)
- Environment Variables: Encrypted with KMS
- Execution Role: Separate from function permissions
- Timeout: 60 seconds
- Memory: 512 MB

### 3. Secrets Manager
**Purpose:** Store and rotate database credentials
**Security Controls:**
- Encryption: KMS encrypted
- Rotation: Automatic every 30 days
- Access: IAM policy (Lambda only)
- Versioning: Automatic (AWSCURRENT/AWSPREVIOUS)
- Audit: CloudTrail logs all access

### 4. KMS Customer Master Key
**Purpose:** Central encryption key for all services
**Security Controls:**
- Key Policy: Explicit allow for services
- Rotation: Automatic every 365 days
- Deletion: 30-day waiting period
- Usage: CloudTrail logs all operations
- Multi-region: Replicate to DR region

### 5. RDS MySQL Database
**Purpose:** Store processed order data
**Security Controls:**
- Encryption at Rest: KMS
- Encryption in Transit: SSL/TLS required
- Authentication: IAM database authentication
- Network: Private subnet, security group
- Backups: Encrypted, 7-day retention
- Multi-AZ: High availability

### 6. DynamoDB Audit Table
**Purpose:** Audit trail of all data operations
**Security Controls:**
- Encryption: KMS customer-managed key
- Point-in-time Recovery: Enabled
- Streams: Track all changes
- Access: IAM policy (Lambda only)
- TTL: Delete old audit logs after 1 year

### 7. CloudTrail
**Purpose:** Log all API calls
**Security Controls:**
- Organization trail: All accounts
- S3 bucket: SSE-S3 encrypted
- Log file validation: Enabled
- Insights: Detect unusual activity
- CloudWatch integration: Real-time alerts

### 8. CloudWatch
**Purpose:** Monitoring and alerting
**Security Controls:**
- Log groups: Encrypted with KMS
- Retention: 90 days
- Metric filters: Failed auth, errors
- Alarms: SNS notifications
- Dashboard: Real-time visibility
```

# **STEP 3: THREAT MODEL & MITIGATIONS (15 MIN)**

```markdown
## Threat Analysis

### Threat 1: Unauthorized Data Access
**Threat Actor:** External attacker
**Attack Vector:** Direct S3 bucket access attempt
**Impact:** Confidential customer data exposed
**Likelihood:** High (S3 misconfigurations common)

**Mitigations:**
1. ✅ Block Public Access (account + bucket level)
2. ✅ Bucket policy requires authenticated AWS identity
3. ✅ VPC Endpoint (no internet routing)
4. ✅ CloudTrail + CloudWatch alarm on suspicious access
5. ✅ S3 Access Analyzer (detect unintended access)

**Residual Risk:** Low
**Detection:** CloudTrail event "GetObject" from unauthorized principal
**Response:** Automated Lambda revokes access, notifies security team

---

### Threat 2: Man-in-the-Middle Attack
**Threat Actor:** Network attacker
**Attack Vector:** Intercept data between Lambda and RDS
**Impact:** Database credentials or customer data intercepted
**Likelihood:** Medium (if SSL not enforced)

**Mitigations:**
1. ✅ RDS: SSL/TLS required (parameter group)
2. ✅ Certificate validation (Lambda verifies RDS cert)
3. ✅ VPC private subnets (no internet traffic)
4. ✅ VPC Flow Logs (detect anomalous traffic)
5. ✅ Network ACLs (restrict traffic)

**Residual Risk:** Very Low
**Detection:** VPC Flow Logs show unexpected connections
**Response:** Automated security group update blocks traffic

---

### Threat 3: Credential Compromise
**Threat Actor:** Insider threat or malware
**Attack Vector:** Stolen database password from code/logs
**Impact:** Direct database access, data breach
**Likelihood:** High (hardcoded passwords common mistake)

**Mitigations:**
1. ✅ NO passwords in code (Secrets Manager)
2. ✅ IAM database authentication (15-min tokens)
3. ✅ Automatic rotation (30 days)
4. ✅ CloudTrail logs all Secrets access
5. ✅ Lambda env vars encrypted with KMS
6. ✅ Least privilege IAM (Lambda can only read, not update secrets)

**Residual Risk:** Very Low
**Detection:** CloudTrail unusual GetSecretValue calls
**Response:** Rotate secret immediately, investigate source

---

### Threat 4: Ransomware / Data Deletion
**Threat Actor:** Ransomware or malicious admin
**Attack Vector:** Mass deletion of S3 objects or RDS data
**Impact:** Data loss, business disruption
**Likelihood:** Medium (increasing threat)

**Mitigations:**
1. ✅ S3 Versioning (can recover deleted objects)
2. ✅ S3 Object Lock (WORM for critical data)
3. ✅ MFA Delete (prevent unauthorized deletion)
4. ✅ RDS automated backups (7 days, encrypted)
5. ✅ RDS snapshots (manual, retained)
6. ✅ Cross-region replication (disaster recovery)
7. ✅ IAM policies (prevent wildcard delete actions)

**Residual Risk:** Low
**Detection:** CloudWatch metric filter on high delete volume
**Response:** Automated alarm, restore from backup/version

---

### Threat 5: Privilege Escalation
**Threat Actor:** Compromised Lambda function
**Attack Vector:** Lambda attempts to access other AWS services
**Impact:** Lateral movement, broader compromise
**Likelihood:** Medium (if overly permissive IAM)

**Mitigations:**
1. ✅ Least privilege IAM role (only S3, Secrets, RDS)
2. ✅ Resource-based policies (RDS, Secrets allow only this Lambda)
3. ✅ VPC (no internet, limited network access)
4. ✅ CloudTrail + GuardDuty (detect unusual behavior)
5. ✅ Permission boundaries (maximum allowed permissions)
6. ✅ SCP at organization level (deny dangerous actions)

**Residual Risk:** Low
**Detection:** GuardDuty finding "UnauthorizedAccess"
**Response:** Automated disable Lambda function, revoke IAM role

---

### Threat 6: Data Exfiltration
**Threat Actor:** Malicious insider
**Attack Vector:** Download large amounts of data from RDS/S3
**Impact:** Intellectual property theft, compliance violation
**Likelihood:** Low (with proper controls)

**Mitigations:**
1. ✅ VPC Endpoints (no internet gateway)
2. ✅ DynamoDB audit log (all data access recorded)
3. ✅ CloudWatch anomaly detection (unusual query volume)
4. ✅ S3 Access Analyzer (detect external access)
5. ✅ Data classification tags (identify sensitive data)
6. ✅ Macie (detect sensitive data movement)

**Residual Risk:** Very Low
**Detection:** CloudWatch alarm on data transfer spikes
**Response:** Automated rate limiting, security investigation

---

### Summary:
- 6 threats identified
- 30+ mitigations implemented
- All threats reduced to Low or Very Low risk
- Multiple layers of defense (defense in depth)
- Automated detection and response
```
