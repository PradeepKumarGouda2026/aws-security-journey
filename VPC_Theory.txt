# **PART 1: VPC SECURITY CONCEPTS (45 MIN)**

## **What is a VPC?**

```
VPC = Virtual Private Cloud

Your own isolated network in AWS cloud:
├─ Complete control over IP addressing
├─ Subnet creation (public/private)
├─ Route table configuration
├─ Network gateways
└─ Security controls

Think: Your own data center in AWS, but software-defined! 🏢
```

## **VPC Components - Security Perspective:**

### **1. Subnets (Network Segmentation)**

```
Public Subnet:
├─ Has route to Internet Gateway (IGW)
├─ Resources get public IPs
├─ Use for: Web servers, bastion hosts, NAT gateways
└─ Security: Minimal attack surface

Private Subnet:
├─ NO direct internet access
├─ Resources use private IPs only
├─ Use for: Databases, app servers, sensitive data
└─ Security: Maximum protection

Example Architecture:

┌─────────────────────────────────────────────┐
│                  VPC                        │
│              10.0.0.0/16                    │
│                                             │
│  ┌──────────────────┐  ┌──────────────────┐│
│  │  Public Subnet   │  │  Private Subnet  ││
│  │   10.0.1.0/24    │  │   10.0.2.0/24    ││
│  │                  │  │                  ││
│  │  ┌──────────┐    │  │  ┌──────────┐    ││
│  │  │ Web      │    │  │  │ Database │    ││
│  │  │ Server   │────┼──┼─▶│          │    ││
│  │  └──────────┘    │  │  └──────────┘    ││
│  │       ↕          │  │                  ││
│  └───────┼──────────┘  └──────────────────┘│
│          ↕                                  │
└──────────┼──────────────────────────────────┘
           ↕
    Internet Gateway
           ↕
        Internet

Web server can talk to internet ✅
Database CANNOT talk to internet ✅
Database only accessible from web server ✅
```

---

### **2. Security Groups (Instance Firewall)**

```
Security Group = Virtual firewall for EC2 instances

Key characteristics:
├─ STATEFUL (return traffic automatically allowed)
├─ Instance-level (attached to ENI)
├─ Only ALLOW rules (no deny rules)
├─ Default: Deny all inbound, allow all outbound
└─ Can reference other security groups

Example:

Web Server Security Group (web-sg):
Inbound:
├─ HTTP (80) from 0.0.0.0/0 ✅ (internet)
├─ HTTPS (443) from 0.0.0.0/0 ✅ (internet)
└─ SSH (22) from 203.0.113.0/24 ✅ (office IP only!)

Outbound:
└─ All traffic (default) ✅

Database Security Group (db-sg):
Inbound:
├─ MySQL (3306) from web-sg ✅ (only web servers!)
└─ DENY everything else (implicit)

Outbound:
└─ All traffic ✅

Security group chaining! 🔗
Web server references db-sg, so only web servers can access DB
```

---

### **3. Network ACLs (Subnet Firewall)**

```
NACL = Network Access Control List

Key characteristics:
├─ STATELESS (must allow return traffic explicitly)
├─ Subnet-level (applies to all instances in subnet)
├─ ALLOW and DENY rules
├─ Rules numbered (processed in order)
└─ Default: Allow all traffic

Example:

Public Subnet NACL:
Inbound:
├─ Rule 100: Allow HTTP (80) from 0.0.0.0/0
├─ Rule 110: Allow HTTPS (443) from 0.0.0.0/0
├─ Rule 120: Allow SSH (22) from 203.0.113.0/24
├─ Rule 130: Allow ephemeral ports (1024-65535) from 0.0.0.0/0
└─ Rule *: Deny all

Outbound:
├─ Rule 100: Allow HTTP (80) to 0.0.0.0/0
├─ Rule 110: Allow HTTPS (443) to 0.0.0.0/0
├─ Rule 120: Allow ephemeral ports (1024-65535) to 0.0.0.0/0
└─ Rule *: Deny all

Stateless = pain! Must allow return traffic manually!
```

---

### **4. Route Tables (Traffic Direction)**

```
Route Table = Rules for where traffic goes

Public Subnet Route Table:
Destination         Target
10.0.0.0/16        local (within VPC)
0.0.0.0/0          igw-abc123 (Internet Gateway)

Private Subnet Route Table:
Destination         Target
10.0.0.0/16        local (within VPC)
0.0.0.0/0          nat-xyz789 (NAT Gateway in public subnet)


Security implications:
├─ Public subnet can send/receive from internet
├─ Private subnet can initiate to internet (via NAT)
├─ Private subnet CANNOT receive from internet
└─ Prevents direct internet exposure! 🛡️
```

---

### **5. Internet Gateway (IGW)**

```
IGW = VPC's door to the internet

Characteristics:
├─ One per VPC
├─ Highly available (AWS managed)
├─ Horizontally scaled
├─ No bandwidth constraints
└─ Free!

Security:
├─ Only attached to VPC (not subnet)
├─ Public subnets route 0.0.0.0/0 to IGW
├─ Resources need public IP/Elastic IP
└─ Security groups still apply! (not bypassed)
```

---

### **6. NAT Gateway (Outbound Internet for Private)**

```
NAT Gateway = One-way internet for private subnets

Purpose:
├─ Private subnet instances can download updates
├─ Can call external APIs
├─ But CANNOT receive inbound from internet
└─ Hides private IPs (source NAT)

Placement:
├─ Must be in PUBLIC subnet
├─ Needs Elastic IP
├─ Private subnets route 0.0.0.0/0 to NAT Gateway
└─ NAT Gateway routes to IGW

Cost: ~$32/month + $0.045/GB data processed

Security benefit:
✅ Private instances never exposed to internet
✅ Only outbound initiated connections
✅ Inbound blocked by design
```

---

### **7. VPC Peering (VPC-to-VPC)**

```
VPC Peering = Private connection between VPCs

Use cases:
├─ Connect dev and prod VPCs
├─ Connect VPCs in different regions
├─ Connect VPCs in different accounts
└─ Share resources privately

Security:
├─ Traffic never touches internet
├─ Uses AWS private backbone
├─ Security groups can reference peer VPC
└─ Must configure route tables

Example:
VPC A (10.0.0.0/16) ←→ VPC B (172.16.0.0/16)
Route in VPC A: 172.16.0.0/16 → pcx-abc123
Route in VPC B: 10.0.0.0/16 → pcx-abc123
```

---

### **8. VPC Endpoints (Private AWS Service Access)**

```
VPC Endpoint = Access AWS services without internet

Types:

Interface Endpoint (PrivateLink):
├─ ENI with private IP in your VPC
├─ Most AWS services (S3, DynamoDB, SNS, etc.)
├─ Cost: ~$7/month per endpoint
└─ Security: Never leaves AWS network

Gateway Endpoint:
├─ Route table entry (no IP address)
├─ Only S3 and DynamoDB
├─ FREE! ✅
└─ Security: Traffic stays in AWS

Example:
Without endpoint: EC2 → NAT → IGW → Internet → S3
With endpoint: EC2 → VPC Endpoint → S3 (private!)

Benefits:
✅ Better security (no internet exposure)
✅ Lower latency
✅ Save NAT Gateway costs
✅ PrivateLink = dedicated connection
```

## **VPC Security Best Practices:**

```
1. Network Segmentation:
   ├─ Use multiple subnets (public/private)
   ├─ Isolate tiers (web/app/data)
   └─ Separate VPCs for dev/staging/prod

2. Least Privilege Network Access:
   ├─ Security groups: Allow only what's needed
   ├─ NACLs: Add deny rules for known bad IPs
   └─ Route tables: Minimal routing

3. Defense in Depth:
   ├─ Security Groups (instance level)
   ├─ NACLs (subnet level)
   ├─ WAF (application level)
   └─ GuardDuty (threat detection)

4. Private by Default:
   ├─ Most resources in private subnets
   ├─ Use VPC endpoints for AWS services
   ├─ NAT Gateway for outbound only
   └─ No public IPs unless absolutely necessary

5. Monitoring:
   ├─ Enable VPC Flow Logs
   ├─ Monitor with CloudWatch
   ├─ Alert on security group changes
   └─ Regular access reviews

6. Encryption in Transit:
   ├─ VPC traffic unencrypted by default
   ├─ Use TLS/SSL for sensitive data
   ├─ IPSec VPN for site-to-site
   └─ PrivateLink for service connections
```
