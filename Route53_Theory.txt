## **PART 1: ROUTE 53 DNSSEC - THEORY (30 MIN)**

### **What is DNS Security Extensions (DNSSEC)?**

```
Problem: DNS is vulnerable to attacks

DNS WITHOUT DNSSEC:
User: "What's IP of bank.com?"
DNS Server: "It's 203.0.113.5"
User: Trusts this blindly ❌

Attacker can:
├─ DNS Spoofing (fake response)
├─ DNS Cache Poisoning
├─ Man-in-the-Middle (MITM)
└─ User connects to attacker's server instead!

Result: User types password → Attacker steals it 😱

DNSSEC = Cryptographic signatures for DNS records
└─ Proves DNS response is authentic
└─ Can't be tampered with
```

---

### **How DNSSEC Works:**

```
DNSSEC Chain of Trust:

. (root)
  ↓ signed
.com
  ↓ signed
example.com
  ↓ signed
www.example.com → 192.0.2.1

Each level signs the next level
└─ Creates "chain of trust" from root to your domain

Verification:
1. User queries www.example.com
2. Resolver checks signature at each level
3. If ALL signatures valid → response trusted ✅
4. If ANY signature invalid → response rejected ❌

Protection:
✅ Prevents DNS spoofing
✅ Prevents cache poisoning
✅ Proves authenticity
❌ Does NOT encrypt (use DNS over HTTPS/TLS for that)
```

---

### **DNSSEC Records:**

```
New DNS Record Types:

RRSIG (Resource Record Signature)
├─ Digital signature for a record
└─ Example: RRSIG for A record of www.example.com

DNSKEY (DNS Public Key)
├─ Public key used to verify signatures
└─ Two types: ZSK (Zone Signing Key) and KSK (Key Signing Key)

DS (Delegation Signer)
├─ Hash of child zone's DNSKEY
├─ Stored in parent zone
└─ Links child zone to parent (creates chain of trust)

NSEC/NSEC3 (Next Secure)
├─ Proves non-existence of records
└─ "example.org does NOT exist" (authenticated)

How They Work Together:
1. AWS signs your zone with DNSKEY
2. Creates RRSIG for each record
3. Publishes DS record to parent zone (.com registry)
4. Resolver verifies: Root → .com → example.com → www
```

---

### **AWS Route 53 DNSSEC Implementation:**

```
AWS Manages Everything:

Automatic:
✅ Key generation (KSK + ZSK)
✅ Zone signing (creates RRSIG records)
✅ Key rotation (every 90 days for ZSK)
✅ NSEC3 records (authenticated denial)

You Must Do:
⚠️ Establish chain of trust
   └─ Add DS record to parent zone (domain registrar)

Two Modes:

1. Signing (AWS managed keys)
   ├─ AWS creates and manages keys
   ├─ Easiest approach
   └─ AWS handles rotation

2. Signing with Customer-Managed Keys (KMS)
   ├─ You control KSK in AWS KMS
   ├─ More control
   └─ Use for compliance requirements

Cost:
├─ Hosted zone: $0.50/month
├─ DNSSEC signing: $0.50/month additional
└─ Total: $1/month per zone
```

---

### **When to Use DNSSEC:**

```
USE DNSSEC when:
✅ Financial services (banking, payments)
✅ Government/defense
✅ Healthcare (HIPAA)
✅ High-value targets
✅ Compliance requirements (some regulations mandate)
✅ Brand protection (prevent phishing via DNS)

SKIP DNSSEC when:
❌ Low-risk websites (blogs, marketing sites)
❌ Internal-only domains
❌ Development/testing environments
❌ Cost-sensitive projects ($0.50/mo matters)

Reality Check:
├─ <5% of domains use DNSSEC (as of 2024)
├─ Complex to implement (outside AWS)
├─ AWS makes it EASY (just enable it!)
└─ But still optional for most use cases

Exam Tip: Know WHAT it does, WHEN to use, HOW AWS implements
```

## **PART 2: ROUTE 53 RESOLVER DNS FIREWALL - THEORY (20 MIN)**

### **What is DNS Firewall?**

```
Problem: Users/Applications query malicious domains

Scenario:
Employee clicks phishing link → Laptop tries to resolve "malicious-site.com"
OR
Malware installed → Tries to contact command-and-control (C2) server

DNS Firewall = Block DNS queries to known bad domains

Works at DNS resolution level:
User/App: "What's IP of malicious-site.com?"
DNS Firewall: "BLOCKED! Not resolving that." ❌

Result:
✅ Malicious site unreachable (even if user types URL)
✅ Malware can't call home to C2 server
✅ Protection at network level (all devices)
```

---

### **How It Works:**

```
Architecture:

VPC → Route 53 Resolver → DNS Firewall → Internet DNS

DNS Firewall sits BETWEEN your VPC and external DNS

Query Flow:
1. EC2 instance queries "facebook.com"
2. Route 53 Resolver receives query
3. DNS Firewall checks rules:
   - Is domain in blocklist? → BLOCK
   - Is domain in allowlist? → ALLOW
   - No match? → Use default action
4. If allowed: Resolver queries Internet DNS
5. Response returned to EC2

Protection:
✅ Blocks malicious domains (malware, phishing)
✅ Blocks unwanted domains (social media, gambling)
✅ Compliance (prevent access to prohibited sites)
✅ Centralized (applies to entire VPC)
```

---

### **Domain Lists:**

```
Three Types of Lists:

1. AWS MANAGED DOMAIN LISTS (FREE!)
   ├─ AWSManagedDomainsMalwareDomainList
   │   └─ Known malware distribution sites
   │   └─ Updated by AWS automatically
   │   └─ ~100,000+ domains
   │
   ├─ AWSManagedDomainsBotnetCommandAndControlDomainList
   │   └─ Known C2 servers
   │   └─ Botnet infrastructure
   │   └─ Updated daily
   │
   └─ AWSManagedDomainsAggregateThreatList
       └─ Combination of multiple threat feeds
       └─ Highest coverage
       └─ Recommended starting point

2. CUSTOM DOMAIN LISTS (You create)
   ├─ Your own blocklist
   ├─ Example: Block social media for corporate policy
   ├─ Example: Block competitors' sites
   └─ Maximum: 1,000-5,000 domains per list

3. PARTNER/THIRD-PARTY LISTS (Coming Soon)
   └─ Integration with threat intelligence vendors

Rule Actions:
├─ ALLOW: Permit DNS resolution
├─ BLOCK: Refuse to resolve (return NXDOMAIN)
├─ ALERT: Log but allow (monitoring mode)
└─ OVERRIDE: Custom response (redirect to safe page)
```

---

### **DNS Firewall Rules:**

```
Rule Structure:

Rule Group → Contains Multiple Rules → Applied to VPC

Example Rule Group: "Corporate Security Rules"
├─ Rule 1 (Priority 100): BLOCK AWS Managed Malware List
├─ Rule 2 (Priority 200): BLOCK Custom Social Media List
├─ Rule 3 (Priority 300): ALLOW AWS Services (*.amazonaws.com)
└─ Default Action: ALLOW (everything else)

Rule Evaluation:
1. Rules evaluated in priority order (lowest number first)
2. First match wins
3. No match → Default action

Example:
Query: malware-site.com
├─ Rule 1: Matches malware list → BLOCK ✅ (stops here)
└─ Never reaches Rules 2 or 3

Query: facebook.com
├─ Rule 1: No match (not malware)
├─ Rule 2: Matches social media list → BLOCK ✅ (stops here)
└─ Never reaches Rule 3

Query: s3.amazonaws.com
├─ Rule 1: No match
├─ Rule 2: No match
├─ Rule 3: Matches AWS services → ALLOW ✅
└─ Resolved normally

Query: google.com
├─ Rule 1: No match
├─ Rule 2: No match
├─ Rule 3: No match
└─ Default Action: ALLOW ✅
```

# **LAB 91: DEPLOY ROUTE 53 RESOLVER DNS FIREWALL**

```bash
#!/bin/bash
# CloudShell - Route 53 Resolver DNS Firewall Lab

echo "╔═══════════════════════════════════════════════════════════╗"
echo "║      LAB 91: ROUTE 53 RESOLVER DNS FIREWALL             ║"
echo "╚═══════════════════════════════════════════════════════════╝"
echo ""

echo "What we'll build:"
echo "  • VPC with DNS Firewall protection"
echo "  • Rule group with AWS Managed malware list"
echo "  • Custom domain list (block social media)"
echo "  • Test DNS resolution (allowed vs blocked)"
echo ""
echo "Time: ~20 minutes"
echo "Cost: ~$0.10 for testing (delete after!)"
echo ""

#############################################################################
# STEP 1: CREATE VPC FOR TESTING
#############################################################################

echo "Step 1: Creating VPC for DNS Firewall Testing"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

DNS_FW_VPC=$(aws ec2 create-vpc \
  --cidr-block 10.5.0.0/16 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=DNS-Firewall-VPC}]' \
  --query 'Vpc.VpcId' \
  --output text)

echo "  ✅ VPC created: $DNS_FW_VPC"

# Enable DNS
aws ec2 modify-vpc-attribute --vpc-id $DNS_FW_VPC --enable-dns-hostnames
aws ec2 modify-vpc-attribute --vpc-id $DNS_FW_VPC --enable-dns-support

echo "  ✅ DNS enabled"
echo ""

# Create subnet
DNS_FW_SUBNET=$(aws ec2 create-subnet \
  --vpc-id $DNS_FW_VPC \
  --cidr-block 10.5.1.0/24 \
  --availability-zone us-east-1a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=DNS-Firewall-Subnet}]' \
  --query 'Subnet.SubnetId' \
  --output text)

aws ec2 modify-subnet-attribute --subnet-id $DNS_FW_SUBNET --map-public-ip-on-launch

echo "  ✅ Subnet created: $DNS_FW_SUBNET"
echo ""

# Create IGW
DNS_FW_IGW=$(aws ec2 create-internet-gateway \
  --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=DNS-Firewall-IGW}]' \
  --query 'InternetGateway.InternetGatewayId' \
  --output text)

aws ec2 attach-internet-gateway --internet-gateway-id $DNS_FW_IGW --vpc-id $DNS_FW_VPC

echo "  ✅ IGW attached: $DNS_FW_IGW"
echo ""

# Route table
DNS_FW_RT=$(aws ec2 create-route-table \
  --vpc-id $DNS_FW_VPC \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=DNS-Firewall-RT}]' \
  --query 'RouteTable.RouteTableId' \
  --output text)

aws ec2 create-route --route-table-id $DNS_FW_RT --destination-cidr-block 0.0.0.0/0 --gateway-id $DNS_FW_IGW
aws ec2 associate-route-table --route-table-id $DNS_FW_RT --subnet-id $DNS_FW_SUBNET

echo "  ✅ Route table configured"
echo ""

#############################################################################
# STEP 2: CREATE CUSTOM DOMAIN LIST (Block Social Media)
#############################################################################

echo "Step 2: Creating Custom Domain List (Social Media Blocklist)"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

echo "  Creating domain list with social media sites..."
echo ""

DOMAIN_LIST_ID=$(aws route53resolver create-firewall-domain-list \
  --name SocialMediaBlocklist \
  --tags Key=Name,Value=SocialMediaBlocklist \
  --query 'FirewallDomainList.Id' \
  --output text)

echo "  ✅ Domain list created: $DOMAIN_LIST_ID"
echo ""

# Add domains to the list
echo "  Adding domains to blocklist..."

# Create a file with domains
cat > /tmp/blocked-domains.txt << 'EOF'
facebook.com
twitter.com
instagram.com
tiktok.com
reddit.com
snapchat.com
linkedin.com
youtube.com
EOF

echo ""
echo "  Domains to block:"
cat /tmp/blocked-domains.txt
echo ""

# Add domains to the firewall domain list
# Note: We add them one at a time in this example
while IFS= read -r domain; do
    aws route53resolver update-firewall-domains \
      --firewall-domain-list-id $DOMAIN_LIST_ID \
      --operation ADD \
      --domains "$domain" 2>/dev/null
    echo "    • Added: $domain"
done < /tmp/blocked-domains.txt

echo ""
echo "  ✅ All domains added to blocklist"
echo ""

#############################################################################
# STEP 3: CREATE FIREWALL RULE GROUP
```

## **VPC PEERING SECURITY - THEORY (15 MIN)**

### **What is VPC Peering?**

```
VPC Peering = Private connection between two VPCs

Without Peering:
VPC A (10.0.0.0/16) ←→ Internet ←→ VPC B (10.1.0.0/16)
├─ Traffic goes through public internet
├─ Need public IPs or NAT Gateway
├─ Less secure, slower, costs more
└─ No private connectivity

With Peering:
VPC A (10.0.0.0/16) ←――――――――――→ VPC B (10.1.0.0/16)
                    Peering Connection
├─ Traffic stays on AWS network (private)
├─ Use private IPs
├─ Secure, fast, cheaper
└─ Like they're one big network
```

---

### **VPC Peering Architecture:**


### **VPC Peering Security Considerations:**

```
SECURITY GROUPS WITH PEERING:

Problem: Can't reference security group from another account/region

Solution: Use CIDR blocks instead

Example:
VPC A Security Group (DB tier):
┌────────────────────────────────────────────┐
│ Inbound Rules:                             │
│ ┌────────────┬──────┬─────────────────┐   │
│ │ Type       │ Port │ Source          │   │
│ ├────────────┼──────┼─────────────────┤   │
│ │ PostgreSQL │ 5432 │ 10.1.0.0/16    │   │  ← VPC B CIDR
│ └────────────┴──────┴─────────────────┘   │
└────────────────────────────────────────────┘

Why CIDR block?
├─ Can't reference sg-xyz from VPC B (different account/region)
├─ Must use IP range instead
└─ Less granular, but works

Best Practice:
├─ Use smallest CIDR possible (not entire VPC)
├─ Example: 10.1.2.0/24 (just app subnet) instead of 10.1.0.0/16
└─ Minimize exposure

SAME ACCOUNT/SAME REGION:
Can reference security group IDs! ✅
Example: Source: sg-0123456789abcdef (from peered VPC)
```

### **VPC Peering Limitations:**

```
CRITICAL LIMITATIONS:

1. NO TRANSITIVE PEERING ⚠️
   
   VPC A ←――→ VPC B ←――→ VPC C
   
   VPC A CANNOT talk to VPC C!
   ├─ Peering is 1:1 only
   ├─ Need separate peering: A ←――→ C
   └─ Gets messy with many VPCs (full mesh)
   
   Example with 5 VPCs:
   ├─ Need: 5 × 4 / 2 = 10 peering connections
   ├─ With 10 VPCs: 45 peering connections! 😱
   └─ Solution: Transit Gateway (next topic)

2. NO OVERLAPPING CIDR BLOCKS ⚠️
   
   VPC A: 10.0.0.0/16
   VPC B: 10.0.0.0/16  ❌ CANNOT peer!
   
   Same CIDR = routing conflict
   └─ Plan VPC CIDRs carefully!

3. NO EDGE-TO-EDGE ROUTING ⚠️
   
   VPC A (has VPN) ←――→ VPC B
                          ↓
                     On-premises
   
   VPC B CANNOT use VPC A's VPN to reach on-prem ❌
   ├─ Each VPC needs its own VPN/Direct Connect
   └─ Peering only works for VPC-to-VPC

4. DNS RESOLUTION
   
   By default: Private DNS doesn't work across peering ❌
   
   Must enable:
   ├─ Accepter DNS resolution: ON
   ├─ Requester DNS resolution: ON
   └─ Then: ip-10-0-1-5.ec2.internal resolves ✅

5. MAXIMUM PEERING CONNECTIONS
   
   Per VPC: 125 active peering connections
   └─ If you need more: Use Transit Gateway
```

## **AWS TRANSIT GATEWAY - THEORY (20 MIN)**

### **What is Transit Gateway?**

```
Transit Gateway = Hub for connecting VPCs and on-premises networks

Think of it as a cloud router:
├─ All VPCs connect to Transit Gateway (TGW)
├─ TGW routes traffic between them
├─ Simplifies network architecture
└─ Enables transitive routing

Without Transit Gateway (Full Mesh):
┌────────┐     ┌────────┐
│ VPC 1  │─────│ VPC 2  │
└───┬────┘     └───┬────┘
    │ \          / │
    │   \      /   │
    │     \  /     │
    │      \/      │
    │      /\      │
    │    /    \    │
    │  /        \  │
┌───▼──┐      ┌───▼──┐
│VPC 3 │──────│VPC 4 │
└──────┘      └──────┘

4 VPCs = 6 peering connections! 😵

With Transit Gateway (Hub-and-Spoke):
       ┌────────┐
       │ VPC 1  │
       └───┬────┘
           │
       ┌───▼────────┐
       │            │
┌──────┤  Transit   ├──────┐
│      │  Gateway   │      │
│      │            │      │
│      └────────────┘      │
│                          │
┌▼──────┐              ┌───▼──┐
│ VPC 2 │              │ VPC 3│
└───────┘              └──────┘

4 VPCs = 4 attachments ✅
Much simpler!
```

### **Transit Gateway Security Features:**

```
1. NETWORK SEGMENTATION
   
   Separate route tables for different environments:
   
   Production Route Table:
   ├─ Can route to: Prod VPC, Shared Services VPC
   └─ CANNOT route to: Dev VPC, Test VPC
   
   Development Route Table:
   ├─ Can route to: Dev VPC, Test VPC, Shared Services
   └─ CANNOT route to: Prod VPC
   
   Result: Dev can't accidentally talk to Prod! ✅

2. INSPECTION VPC (Security Hub-and-Spoke)
   
   Architecture:
   All VPCs → Transit Gateway → Inspection VPC → Internet
                                      │
                                Network Firewall
                                      │
                                  IDS/IPS
   
   Inspection VPC contains:
   ├─ Network Firewall (IDS/IPS, domain filtering)
   ├─ Third-party firewall (Palo Alto, Fortinet)
   ├─ Centralized NAT Gateway
   └─ All traffic inspected! 🔍
   
   Routing:
   VPC A wants to reach Internet:
   1. Traffic → TGW
   2. TGW route: 0.0.0.0/0 → Inspection VPC
   3. Inspection VPC → Firewall inspection
   4. If ALLOW → NAT Gateway → Internet
   5. Response → Same path reverse
   
   Benefits:
   ✅ Single security stack (no duplicate firewalls)
   ✅ Centralized logging
   ✅ Easier management
   ✅ Cost-effective at scale

3. ROUTE TABLE ISOLATION
   
   Prevent cross-talk between environments:
   
   Associate VPC with route table:
   ├─ Prod-VPC-1 → Production Route Table
   ├─ Prod-VPC-2 → Production Route Table
   ├─ Dev-VPC-1 → Development Route Table
   └─ Dev-VPC-2 → Development Route Table
   
   Production Route Table knows ONLY:
   ├─ 10.1.0.0/16 (Prod-VPC-1)
   ├─ 10.2.0.0/16 (Prod-VPC-2)
   └─ No routes to Dev VPCs!
   
   Result: Prod can't reach Dev even if misconfigured ✅

4. BLACKHOLE ROUTES
   
   Explicitly block traffic:
   
   Route: 10.10.0.0/16 → Blackhole
   └─ Any traffic to 10.10.0.0/16 is dropped
   
   Use cases:
   ├─ Decommissioned VPC (prevent accidental access)
   ├─ Security incident (isolate compromised VPC)
   └─ Quarantine environment
```

## **AWS PRIVATELINK - THEORY (20 MIN)**

### **What is AWS PrivateLink?**

```
PrivateLink = Private connectivity to AWS services and your own services

Problem WITHOUT PrivateLink:
├─ VPC A needs to access service in VPC B
├─ Options:
│   ├─ VPC Peering (exposes entire VPC)
│   ├─ Public endpoint (goes through internet)
│   └─ Transit Gateway (complex for simple use case)
└─ None are ideal for service-to-service connectivity

With PrivateLink:
├─ Private, secure, one-way connection
├─ Expose ONLY specific service (not entire VPC)
├─ Traffic stays on AWS network
├─ Scalable, no IP conflicts
└─ Service consumer doesn't see provider's VPC

Use Case:
VPC A (Customer) wants to use SaaS app in VPC B (SaaS Provider)
├─ Provider creates VPC Endpoint Service (powered by NLB)
├─ Customer creates VPC Endpoint
├─ Customer accesses via private IP (10.x.x.x)
└─ Provider's VPC remains private/hidden
```

### **PrivateLink Components:**

```
1. VPC ENDPOINT SERVICE (Provider Side)
   
   Created by: Service provider
   Powered by: Network Load Balancer (NLB)
   
   Configuration:
   ├─ Choose NLB (must be internal or internet-facing)
   ├─ Set acceptance mode (auto-accept or manual approval)
   ├─ Specify allowed principals (AWS accounts/IAM principals)
   └─ Optional: Private DNS name
   
   Features:
   ✅ Control who can connect
   ✅ Audit connection requests
   ✅ Auto-scaling (NLB handles load)
   ✅ HA across multiple AZs

2. VPC ENDPOINT (Consumer Side)
   
   Created by: Service consumer
   Type: Interface endpoint
   
   Configuration:
   ├─ Select endpoint service (by service name)
   ├─ Choose VPC and subnets
   ├─ Select security groups
   └─ Enable private DNS (optional)
   
   Features:
   ✅ Gets private IP in consumer VPC
   ✅ Accessible from anywhere in VPC
   ✅ Can enable across multiple AZs (redundancy)
   ✅ Security group controls access

3. NETWORK LOAD BALANCER (Backend)
   
   Purpose: Distributes traffic to targets
   
   Targets:
   ├─ EC2 instances
   ├─ IP addresses (containers)
   ├─ Lambda functions (via ALB → NLB not supported, use ALB)
   └─ Auto Scaling groups
   
   Requirements:
   ├─ Must be internal or internet-facing (NLB)
   ├─ Health checks configured
   ├─ Listener configured (TCP/UDP/TLS)
   └─ Target group with registered targets
```

```bash
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

PROVIDER_VPC=$(aws ec2 create-vpc \
  --cidr-block 10.20.0.0/16 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=Provider-VPC},{Key=Type,Value=ServiceProvider}]' \
  --query 'Vpc.VpcId' \
  --output text)

aws ec2 modify-vpc-attribute --vpc-id $PROVIDER_VPC --enable-dns-hostnames
aws ec2 modify-vpc-attribute --vpc-id $PROVIDER_VPC --enable-dns-support

echo "  ✅ Provider VPC created: $PROVIDER_VPC (10.20.0.0/16)"
echo ""

# Create subnets in TWO AZs (NLB requires multi-AZ)
echo "  Creating subnets in multiple AZs (NLB requirement)..."

PROVIDER_SUBNET_1=$(aws ec2 create-subnet \
  --vpc-id $PROVIDER_VPC \
  --cidr-block 10.20.1.0/24 \
  --availability-zone us-east-1a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Provider-Subnet-1}]' \
  --query 'Subnet.SubnetId' \
  --output text)

PROVIDER_SUBNET_2=$(aws ec2 create-subnet \
  --vpc-id $PROVIDER_VPC \
  --cidr-block 10.20.2.0/24 \
  --availability-zone us-east-1b \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Provider-Subnet-2}]' \
  --query 'Subnet.SubnetId' \
  --output text)

aws ec2 modify-subnet-attribute --subnet-id $PROVIDER_SUBNET_1 --map-public-ip-on-launch
aws ec2 modify-subnet-attribute --subnet-id $PROVIDER_SUBNET_2 --map-public-ip-on-launch

echo "     ✅ Subnet 1: $PROVIDER_SUBNET_1 (us-east-1a)"
echo "     ✅ Subnet 2: $PROVIDER_SUBNET_2 (us-east-1b)"
echo ""

# Create IGW (for provider instances to download packages)
PROVIDER_IGW=$(aws ec2 create-internet-gateway \
  --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=Provider-IGW}]' \
  --query 'InternetGateway.InternetGatewayId' \
  --output text)

aws ec2 attach-internet-gateway --internet-gateway-id $PROVIDER_IGW --vpc-id $PROVIDER_VPC

echo "  ✅ Internet Gateway attached: $PROVIDER_IGW"
echo ""

# Route table
PROVIDER_RT=$(aws ec2 create-route-table \
  --vpc-id $PROVIDER_VPC \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=Provider-RT}]' \
  --query 'RouteTable.RouteTableId' \
  --output text)

aws ec2 create-route --route-table-id $PROVIDER_RT --destination-cidr-block 0.0.0.0/0 --gateway-id $PROVIDER_IGW
aws ec2 associate-route-table --route-table-id $PROVIDER_RT --subnet-id $PROVIDER_SUBNET_1
aws ec2 associate-route-table --route-table-id $PROVIDER_RT --subnet-id $PROVIDER_SUBNET_2

echo "  ✅ Route table configured"
echo ""

#############################################################################
# STEP 2: LAUNCH API SERVICE INSTANCES (Provider's Application)
#############################################################################

echo "Step 2: Launching API Service Instances (Provider's Application)"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

# Get latest Amazon Linux 2023 AMI
AMI_ID=$(aws ec2 describe-images \
  --owners amazon \
  --filters "Name=name,Values=al2023-ami-2023.*-x86_64" "Name=state,Values=available" \
  --query 'Images | sort_by(@, &CreationDate) | [-1].ImageId' \
  --output text)

echo "  Using AMI: $AMI_ID"
echo ""

# Security group for API service
PROVIDER_SG=$(aws ec2 create-security-group \
  --group-name provider-api-sg \
  --description "Provider API service security group" \
  --vpc-id $PROVIDER_VPC \
  --tag-specifications 'ResourceType=security-group,Tags=[{Key=Name,Value=Provider-API-SG}]' \
  --query 'GroupId' \
  --output text)

# Allow HTTP from anywhere (NLB will forward here)
aws ec2 authorize-security-group-ingress \
  --group-id $PROVIDER_SG \
  --protocol tcp \
  --port 80 \
  --cidr 10.20.0.0/16

echo "  ✅ Security group created: $PROVIDER_SG"
echo "     Allows: HTTP (80) from VPC CIDR"
echo ""

# User data for API service
USER_DATA=$(cat << 'EOF'
#!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd

# Get instance metadata
TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")
INSTANCE_ID=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id)
AZ=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/placement/availability-zone)
PRIVATE_IP=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/local-ipv4)

# Create API response
cat > /var/www/html/index.html << APIEOF
<!DOCTYPE html>
<html>
<head>
    <title>Private API Service</title>
    <style>
        body { 
            font-family: Arial; 
            margin: 50px; 
            background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
            color: white;
        }
        .container { 
            background: rgba(255,255,255,0.1); 
            padding: 30px; 
            border-radius: 10px;
            backdrop-filter: blur(10px);
        }
        h1 { color: #FFD700; }
        .info { 
            background: rgba(0,0,0,0.3); 
            padding: 20px; 
            margin: 20px 0; 
            border-radius: 5px;
            font-family: monospace;
        }
        .success { color: #00ff00; font-weight: bold; }
    </style>
</head>
<body>
    <div class="container">
        <h1>🔐 Private API Service via PrivateLink</h1>
        <p class="success">✅ Connection successful via AWS PrivateLink!</p>
        
        <div class="info">
            <h3>Service Information:</h3>
            <p>Instance ID: $INSTANCE_ID</p>
            <p>Availability Zone: $AZ</p>
            <p>Private IP: $PRIVATE_IP</p>
            <p>Service Type: SaaS Analytics API</p>
            <p>Connection: Private (AWS PrivateLink)</p>
        </div>
        
        <h3>Why This Works:</h3>
        <ul style="line-height: 1.8;">
            <li>✅ You connected via VPC Endpoint (private IP)</li>
            <li>✅ Traffic stayed on AWS private network</li>
            <li>✅ You don't see our VPC (10.20.0.0/16)</li>
            <li>✅ No internet gateway needed</li>
            <li>✅ Secure, scalable, private connectivity</li>
        </ul>
        
        <div class="info">
            <h3>API Endpoint:</h3>
            <p>This is where your application would call our API</p>
            <p>Example: POST /api/analytics/data</p>
            <p>Authentication: Bearer token (not shown)</p>
        </div>
        
        <p><em>Powered by AWS PrivateLink - Enterprise Private Connectivity</em></p>
        <p style="font-size: 0.8em;">Generated at: $(date)</p>
    </div>
</body>
</html>
APIEOF
EOF
)

echo "  Launching API service instances..."

# Launch instance in AZ 1
PROVIDER_INSTANCE_1=$(aws ec2 run-instances \
  --image-id $AMI_ID \
  --instance-type t2.micro \
  --subnet-id $PROVIDER_SUBNET_1 \
  --security-group-ids $PROVIDER_SG \
  --user-data "$USER_DATA" \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=Provider-API-1}]' \
  --query 'Instances[0].InstanceId' \
  --output text)

echo "     ✅ Instance 1 launched: $PROVIDER_INSTANCE_1 (us-east-1a)"

# Launch instance in AZ 2
PROVIDER_INSTANCE_2=$(aws ec2 run-instances \
  --image-id $AMI_ID \
  --instance-type t2.micro \
  --subnet-id $PROVIDER_SUBNET_2 \
  --security-group-ids $PROVIDER_SG \
  --user-data "$USER_DATA" \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=Provider-API-2}]' \
  --query 'Instances[0].InstanceId' \
  --output text)

echo "     ✅ Instance 2 launched: $PROVIDER_INSTANCE_2 (us-east-1b)"
echo ""
echo "  ⏱️  Waiting for instances to be running..."

aws ec2 wait instance-running --instance-ids $PROVIDER_INSTANCE_1 $PROVIDER_INSTANCE_2

echo "     ✅ Both instances are running!"
echo ""

#############################################################################
# STEP 3: CREATE NETWORK LOAD BALANCER
#############################################################################

echo "Step 3: Creating Network Load Balancer (Internal)"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

echo "  Creating Network Load Balancer (internal)..."
echo "  This NLB will be the backend for VPC Endpoint Service"
echo ""

NLB_ARN=$(aws elbv2 create-load-balancer \
  --name PrivateLink-NLB \
  --type network \
  --scheme internal \
  --subnets $PROVIDER_SUBNET_1 $PROVIDER_SUBNET_2 \
  --tags Key=Name,Value=PrivateLink-NLB \
  --query 'LoadBalancers[0].LoadBalancerArn' \
  --output text)

echo "     ✅ NLB created: $NLB_ARN"
echo ""

# Get NLB DNS name
NLB_DNS=$(aws elbv2 describe-load-balancers \
  --load-balancer-arns $NLB_ARN \
  --query 'LoadBalancers[0].DNSName' \
  --output text)

echo "     NLB DNS: $NLB_DNS"
echo "     Type: Internal (no public IP)"
echo ""

# Wait for NLB to be active
echo "  ⏱️  Waiting for NLB to become active (2-3 minutes)..."

while true; do
    STATE=$(aws elbv2 describe-load-balancers \
        --load-balancer-arns $NLB_ARN \
        --query 'LoadBalancers[0].State.Code' \
        --output text)
    
    if [ "$STATE" == "active" ]; then
        echo "     ✅ NLB is active!"
        break
    fi
    
    echo "     State: $STATE (waiting...)"
    sleep 15
done

echo ""

# Create target group
echo "  Creating target group..."

TARGET_GROUP_ARN=$(aws elbv2 create-target-group \
  --name PrivateLink-TG \
  --protocol TCP \
  --port 80 \
  --vpc-id $PROVIDER_VPC \
  --health-check-protocol HTTP \
  --health-check-path / \
  --health-check-interval-seconds 30 \
  --healthy-threshold-count 2 \
  --unhealthy-threshold-count 2 \
  --tags Key=Name,Value=PrivateLink-TG \
  --query 'TargetGroups[0].TargetGroupArn' \
  --output text)

echo "     ✅ Target group created: $TARGET_GROUP_ARN"
echo ""

# Register instances with target group
echo "  Registering instances with target group..."

aws elbv2 register-targets \
  --target-group-arn $TARGET_GROUP_ARN \
  --targets Id=$PROVIDER_INSTANCE_1 Id=$PROVIDER_INSTANCE_2

echo "     ✅ Instances registered:"
echo "        • $PROVIDER_INSTANCE_1"
echo "        • $PROVIDER_INSTANCE_2"
echo ""

# Create listener
echo "  Creating NLB listener (TCP:80)..."

aws elbv2 create-listener \
  --load-balancer-arn $NLB_ARN \
  --protocol TCP \
  --port 80 \
  --default-actions Type=forward,TargetGroupArn=$TARGET_GROUP_ARN

echo "     ✅ Listener created (TCP port 80 → target group)"
echo ""

# Wait for targets to be healthy
echo "  ⏱️  Waiting for targets to become healthy (30-60 seconds)..."
sleep 45

HEALTH=$(aws elbv2 describe-target-health \
  --target-group-arn $TARGET_GROUP_ARN \
  --query 'TargetHealthDescriptions[*].TargetHealth.State' \
  --output text 2>/dev/null)

echo "     Target health: $HEALTH"

if echo "$HEALTH" | grep -q "healthy"; then
    echo "     ✅ At least one target is healthy!"
else
    echo "     ℹ️  Targets still initializing (will be ready soon)"
fi

echo ""

#############################################################################
# STEP 4: CREATE VPC ENDPOINT SERVICE
#############################################################################

echo "Step 4: Creating VPC Endpoint Service (Provider Side)"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

echo "  Creating VPC Endpoint Service..."
echo ""

# Get NLB ARN (we already have it, but showing the pattern)
ENDPOINT_SERVICE=$(aws ec2 create-vpc-endpoint-service-configuration \
  --network-load-balancer-arns $NLB_ARN \
  --acceptance-required \
  --tag-specifications 'ResourceType=vpc-endpoint-service,Tags=[{Key=Name,Value=Private-API-Service}]' \
  --query 'ServiceConfiguration' \
  --output json)

SERVICE_ID=$(echo $ENDPOINT_SERVICE | jq -r '.ServiceId')
SERVICE_NAME=$(echo $ENDPOINT_SERVICE | jq -r '.ServiceName')

echo "     ✅ VPC Endpoint Service created!"
echo ""
echo "     Service ID: $SERVICE_ID"
echo "     Service Name: $SERVICE_NAME"
echo ""
echo "     Configuration:"
echo "       • Acceptance Required: YES (manual approval)"
echo "       • Backend: Network Load Balancer"
echo "       • State: Available"
echo ""
echo "     ℹ️  Customers will use this service name to connect:"
echo "        $SERVICE_NAME"
echo ""

#############################################################################
# STEP 5: CREATE CONSUMER VPC
#############################################################################

echo "Step 5: Creating Consumer VPC (Customer/Client)"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

CONSUMER_VPC=$(aws ec2 create-vpc \
  --cidr-block 10.30.0.0/16 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=Consumer-VPC},{Key=Type,Value=ServiceConsumer}]' \
  --query 'Vpc.VpcId' \
  --output text)

aws ec2 modify-vpc-attribute --vpc-id $CONSUMER_VPC --enable-dns-hostnames
aws ec2 modify-vpc-attribute --vpc-id $CONSUMER_VPC --enable-dns-support

echo "  ✅ Consumer VPC created: $CONSUMER_VPC (10.30.0.0/16)"
echo ""
echo "     Note: Consumer VPC CIDR (10.30.0.0/16) overlaps conceptually"
echo "           with Provider VPC (10.20.0.0/16) but that's OK!"
echo "           PrivateLink solves IP conflict issues! ✅"
echo ""

# Create subnet
CONSUMER_SUBNET=$(aws ec2 create-subnet \
  --vpc-id $CONSUMER_VPC \
  --cidr-block 10.30.1.0/24 \
  --availability-zone us-east-1a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Consumer-Subnet}]' \
  --query 'Subnet.SubnetId' \
  --output text)

aws ec2 modify-subnet-attribute --subnet-id $CONSUMER_SUBNET --map-public-ip-on-launch

echo "  ✅ Subnet created: $CONSUMER_SUBNET"
echo ""

# IGW for consumer (to access internet for testing)
CONSUMER_IGW=$(aws ec2 create-internet-gateway \
  --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=Consumer-IGW}]' \
  --query 'InternetGateway.InternetGatewayId' \
  --output text)

aws ec2 attach-internet-gateway --internet-gateway-id $CONSUMER_IGW --vpc-id $CONSUMER_VPC

# Route table
CONSUMER_RT=$(aws ec2 create-route-table \
  --vpc-id $CONSUMER_VPC \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=Consumer-RT}]' \
  --query 'RouteTable.RouteTableId' \
  --output text)

aws ec2 create-route --route-table-id $CONSUMER_RT --destination-cidr-block 0.0.0.0/0 --gateway-id $CONSUMER_IGW
aws ec2 associate-route-table --route-table-id $CONSUMER_RT --subnet-id $CONSUMER_SUBNET

echo "  ✅ Networking configured"
echo ""

#############################################################################
# STEP 6: CREATE VPC ENDPOINT (Consumer Side)
#############################################################################

echo "Step 6: Creating VPC Endpoint (Consumer Side)"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

echo "  Creating security group for VPC Endpoint..."

ENDPOINT_SG=$(aws ec2 create-security-group \
  --group-name vpc-endpoint-sg \
  --description "Security group for VPC Endpoint" \
  --vpc-id $CONSUMER_VPC \
  --tag-specifications 'ResourceType=security-group,Tags=[{Key=Name,Value=VPC-Endpoint-SG}]' \
  --query 'GroupId' \
  --output text)

# Allow HTTP from consumer VPC
aws ec2 authorize-security-group-ingress \
  --group-id $ENDPOINT_SG \
  --protocol tcp \
  --port 80 \
  --cidr 10.30.0.0/16

echo "     ✅ Endpoint security group: $ENDPOINT_SG"
echo ""

echo "  Creating VPC Endpoint to connect to provider service..."
echo "     Service Name: $SERVICE_NAME"
echo ""

ENDPOINT_ID=$(aws ec2 create-vpc-endpoint \
  --vpc-endpoint-type Interface \
  --service-name $SERVICE_NAME \
  --vpc-id $CONSUMER_VPC \
  --subnet-ids $CONSUMER_SUBNET \
  --security-group-ids $ENDPOINT_SG \
  --tag-specifications 'ResourceType=vpc-endpoint,Tags=[{Key=Name,Value=Private-API-Endpoint}]' \
  --query 'VpcEndpoint.VpcEndpointId' \
  --output text)

echo "     ✅ VPC Endpoint created: $ENDPOINT_ID"
echo ""
echo "     Status: Pending approval from provider"
echo "     Type: Interface endpoint"
echo "     Subnet: $CONSUMER_SUBNET"
echo ""

#############################################################################
# STEP 7: APPROVE ENDPOINT CONNECTION (Provider)
#############################################################################

echo "Step 7: Approving Endpoint Connection (Provider Action)"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

echo "  Provider reviewing connection request..."
echo ""

# Wait a few seconds for the request to register
sleep 10

# Get the connection ID
CONN_ID=$(aws ec2 describe-vpc-endpoint-connections \
  --filters "Name=service-id,Values=$SERVICE_ID" \
  --query 'VpcEndpointConnections[0].VpcEndpointId' \
  --output text)

if [ "$CONN_ID" == "$ENDPOINT_ID" ]; then
    echo "     ✅ Connection request found from: $ENDPOINT_ID"
    echo ""
    
    # Approve the connection
    echo "  Provider approving connection..."
    
    aws ec2 accept-vpc-endpoint-connections \
      --service-id $SERVICE_ID \
      --vpc-endpoint-ids $ENDPOINT_ID
    
    echo "     ✅ Connection approved by provider!"
    echo ""
else
    echo "     ⏱️  Connection request still pending registration..."
    echo "        In production, provider would approve via Console or CLI"
fi

echo "  ⏱️  Waiting for endpoint to become available (1-2 minutes)..."

sleep 60

# Check endpoint status
ENDPOINT_STATE=$(aws ec2 describe-vpc-endpoints \
  --vpc-endpoint-ids $ENDPOINT_ID \
  --query 'VpcEndpoints[0].State' \
  --output text)

echo "     Endpoint state: $ENDPOINT_STATE"

if [ "$ENDPOINT_STATE" == "available" ]; then
    echo "     ✅ VPC Endpoint is available!"
else
    echo "     ℹ️  Endpoint still initializing (state: $ENDPOINT_STATE)"
    echo "        This is normal and will complete soon"
fi

echo ""

# Get endpoint DNS name
ENDPOINT_DNS=$(aws ec2 describe-vpc-endpoints \
  --vpc-endpoint-ids $ENDPOINT_ID \
  --query 'VpcEndpoints[0].DnsEntries[0].DnsName' \
  --output text)

echo "  VPC Endpoint Details:"
echo "     Endpoint ID: $ENDPOINT_ID"
echo "     DNS Name: $ENDPOINT_DNS"
echo "     This is what consumer uses to access the service!"
echo ""

#############################################################################
# STEP 8: LAUNCH TEST INSTANCE IN CONSUMER VPC
#############################################################################

echo "Step 8: Launching Test Instance in Consumer VPC"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

# Security group for consumer instance
CONSUMER_SG=$(aws ec2 create-security-group \
  --group-name consumer-test-sg \
  --description "Consumer test instance" \
  --vpc-id $CONSUMER_VPC \
  --tag-specifications 'ResourceType=security-group,Tags=[{Key=Name,Value=Consumer-Test-SG}]' \
  --query 'GroupId' \
  --output text)

echo "  ✅ Security group created: $CONSUMER_SG"
echo ""

# Launch consumer instance
CONSUMER_INSTANCE=$(aws ec2 run-instances \
  --image-id $AMI_ID \
  --instance-type t2.micro \
  --subnet-id $CONSUMER_SUBNET \
  --security-group-ids $CONSUMER_SG \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=Consumer-Test-Instance}]' \
  --user-data '#!/bin/bash
yum install -y curl' \
  --query 'Instances[0].InstanceId' \
  --output text)

echo "  ✅ Consumer instance launched: $CONSUMER_INSTANCE"
echo ""

aws ec2 wait instance-running --instance-ids $CONSUMER_INSTANCE

echo "  ✅ Instance is running"
echo ""

#############################################################################
# STEP 9: TEST PRIVATELINK CONNECTION
#############################################################################

echo "Step 9: Testing PrivateLink Connection"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo ""

echo "  From consumer VPC, we'll access the provider service via endpoint"
echo ""

# Get endpoint IP
ENDPOINT_IP=$(aws ec2 describe-network-interfaces \
  --filters "Name=vpc-id,Values=$CONSUMER_VPC" "Name=description,Values=*VPC Endpoint Interface*" \
  --query 'NetworkInterfaces[0].PrivateIpAddress' \
  --output text 2>/dev/null)

if [ ! -z "$ENDPOINT_IP" ]; then
    echo "  ✅ VPC Endpoint private IP: $ENDPOINT_IP"
    echo ""
    echo "  Testing connection to endpoint..."
    echo "     URL: http://$ENDPOINT_IP"
    echo ""
    
    # Try to curl from CloudShell (may not work due to network isolation)
    echo "     Note: CloudShell may not be able to reach endpoint directly"
    echo "           In production, test from consumer instance"
    echo ""
else
    echo "  ℹ️  Endpoint interface still being created"
fi

echo "  To test from consumer instance (after SSH):"
echo "     curl http://$ENDPOINT_DNS"
echo "     curl http://$ENDPOINT_IP"
echo ""

# SUMMARY
#############################################################################
```

## **LAB 93 KEY LEARNINGS:**

```
╔═══════════════════════════════════════════════════════════╗
║         PRIVATELINK - KEY CONCEPTS LEARNED               ║
╚═══════════════════════════════════════════════════════════╝

ARCHITECTURE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Provider creates:
1. Service (web app, API, database)
2. Network Load Balancer (distributes traffic)
3. VPC Endpoint Service (PrivateLink interface)

Consumer creates:
1. VPC Endpoint in their VPC
2. Endpoint gets private IP in consumer's VPC
3. Consumer app accesses via that private IP

AWS PrivateLink:
• Connects endpoint to service
• Traffic stays on AWS network (private)
• Encrypted automatically
• No internet gateway needed

BENEFITS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ Security: Consumer can't access provider's VPC
✅ Scalability: Thousands of consumers supported
✅ No IP conflicts: Works even with overlapping CIDRs
✅ Control: Provider approves each consumer
✅ Simplicity: Consumer doesn't see infrastructure

VS ALTERNATIVES:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PrivateLink vs VPC Peering:
• Peering: Full network access
• PrivateLink: Service-level only ✅

PrivateLink vs Transit Gateway:
• TGW: Good for many-to-many
• PrivateLink: Good for one service, many consumers ✅

PrivateLink vs Public Endpoint:
• Public: Goes through internet, security risk
• PrivateLink: Private AWS network ✅

EXAM TIPS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Know when to use PrivateLink:
✅ SaaS provider with multiple customers
✅ Shared services (AD, DNS) for many VPCs
✅ Need to hide provider infrastructure
✅ IP overlap between VPCs
✅ One-way connectivity (consumer → provider only)

Don't use PrivateLink for:
❌ Full VPC-to-VPC connectivity (use peering)
❌ Transitive routing (use Transit Gateway)
❌ Just 2 VPCs that need full access (use peering)

Components to remember:
• NLB (required on provider side)
• VPC Endpoint Service (provider creates)
• VPC Endpoint (consumer creates)
• Interface endpoint (gets private IP in consumer VPC)

Cost: $0.01/hour per endpoint + NLB cost
```
