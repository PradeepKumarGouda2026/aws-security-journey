## **Security Hub Concepts:**

### **1. Findings:**

```
Finding = Security issue detected by a service

Example GuardDuty Finding in Security Hub:
┌─────────────────────────────────────────┐
│ Title: Bitcoin mining activity          │
│ Severity: High (8.0)                    │
│ Source: Amazon GuardDuty                │
│ Resource: i-abc123                      │
│ Status: Active                          │
│ First seen: 2026-03-03 10:00           │
│ Updated: 2026-03-03 10:00              │
└─────────────────────────────────────────┘

All findings normalized to AWS Security Finding Format (ASFF)
```

---

### **2. Insights:**

```
Insight = Filtered view of findings

Built-in Insights:
├─ AWS resources with most findings
├─ S3 buckets with public read or write permissions
├─ AMIs that are generating findings
├─ EC2 instances associated with known threats
└─ IAM users with suspicious activity

Custom Insights:
├─ Create your own filters
├─ Group findings by any attribute
└─ Save for recurring analysis

Example:
"Show me all CRITICAL findings in production 
 from the last 7 days"
```

---

### **3. Security Standards:**

```
Standard = Set of compliance checks

CIS AWS Foundations Benchmark:
├─ 43 controls
├─ Best practices for AWS configuration
├─ Example: "Ensure MFA is enabled for root"
├─ Status: PASSED, FAILED, or NOT_AVAILABLE
└─ Score: 87% compliance

PCI-DSS v3.2.1:
├─ 38 controls
├─ Payment Card Industry requirements
├─ Example: "Ensure CloudTrail is enabled"
└─ Score: 92% compliance

AWS Foundational Security Best Practices:
├─ 100+ controls
├─ AWS recommended security configurations
├─ Example: "S3 buckets should have encryption"
└─ Score: 95% compliance

Each control = automated check run continuously
```

---

### **4. Security Score:**

```
Security Score = Overall security posture (0-100)

Calculation:
Score = (Passed controls / Total controls) × 100

Example:
├─ Total controls enabled: 150
├─ Passed: 135
├─ Failed: 15
└─ Score: 90/100 (Good!) 🟢

Score ranges:
├─ 90-100: Excellent 🟢
├─ 75-89: Good 🟡
├─ 50-74: Fair 🟠
└─ 0-49: Poor 🔴

Your score is visible to management/auditors
```

---

### **5. AWS Security Finding Format (ASFF):**

```
ASFF = Standardized JSON schema for all findings

Every finding has:
├─ SchemaVersion
├─ Id (unique identifier)
├─ ProductArn (which service found it)
├─ GeneratorId
├─ AwsAccountId
├─ Types (category)
├─ CreatedAt, UpdatedAt
├─ Severity (0.0-100.0)
├─ Title, Description
├─ Remediation (how to fix)
├─ Resources (what's affected)
├─ Compliance (which standards violated)
└─ RecordState (ACTIVE, ARCHIVED, SUPPRESSED)

Standardization allows:
✅ Cross-service correlation
✅ Unified filtering
✅ Consistent prioritization
✅ Automated workflows
```
