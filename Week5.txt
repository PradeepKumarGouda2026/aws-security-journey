```
╔═══════════════════════════════════════════════════════════╗
║        WHY IAM IS THE MOST IMPORTANT TOPIC               ║
╚═══════════════════════════════════════════════════════════╝

EXAM STATISTICS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

• 22% of exam questions are DIRECTLY about IAM
• 60% of exam questions involve IAM in some way
• Most failed questions involve policy evaluation logic
• Highest correlation with passing score

Example:
"A user can't access S3. Why?"
→ Could be: IAM policy, bucket policy, SCP, NACL, SG, VPC endpoint
→ Need to understand IAM evaluation logic! ✅

REAL-WORLD IMPACT:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

• 95% of AWS security incidents involve IAM misconfiguration
• Overly permissive policies = #1 security risk
• Interview questions always cover IAM
• Every AWS service uses IAM

COMPLEXITY:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

IAM Policy Evaluation Logic involves:
1. Identity-based policies (attached to user/role)
2. Resource-based policies (attached to resource)
3. Service Control Policies (SCPs - Organizations)
4. Permissions boundaries (limits)
5. Session policies (temporary)

ALL evaluated together with complex logic! 🤯

Example scenario:
User has IAM policy: "Allow S3:*"
But SCP says: "Deny S3:DeleteBucket"
Result: User CANNOT delete buckets (explicit deny wins)

You MUST understand this cold! ❄️
```
