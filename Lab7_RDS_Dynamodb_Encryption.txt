# **LAB 31: RDS ENCRYPTION IN TRANSIT (SSL/TLS)**

## **What is Encryption in Transit?**

```
At Rest: Data encrypted on disk (KMS)
In Transit: Data encrypted over network (SSL/TLS)

RDS supports SSL/TLS connections:
├─ Client connects with SSL
├─ Traffic encrypted between client and database
└─ Prevents man-in-the-middle attacks
```

---

## **Lab 31.1: Download RDS Certificate**

```bash
# Download RDS root certificate
wget https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem

# This certificate validates RDS server identity
```

---

## **Lab 31.2: Connect with SSL**

```bash
# Connect to RDS with SSL
mysql -h $ENDPOINT -u admin -p \
  --ssl-ca=global-bundle.pem \
  --ssl-mode=REQUIRED

# Enter password

# Verify SSL is active:
mysql> SHOW STATUS LIKE 'Ssl_cipher';

# Output shows:
+---------------+--------------------+
| Variable_name | Value              |
+---------------+--------------------+
| Ssl_cipher    | ECDHE-RSA-AES128-  |
+---------------+--------------------+

✅ SSL/TLS encryption active!
```

---

## **Lab 31.3: Enforce SSL Connections**

**Force ALL connections to use SSL:**

```bash
# Create parameter group
aws rds create-db-parameter-group \
  --db-parameter-group-name mysql-require-ssl \
  --db-parameter-group-family mysql8.0 \
  --description "MySQL parameter group requiring SSL"

# Modify parameter to require SSL
aws rds modify-db-parameter-group \
  --db-parameter-group-name mysql-require-ssl \
  --parameters "ParameterName=require_secure_transport,ParameterValue=ON,ApplyMethod=immediate"

# Apply parameter group to database
aws rds modify-db-instance \
  --db-instance-identifier encrypted-mysql-db \
  --db-parameter-group-name mysql-require-ssl \
  --apply-immediately

# Reboot database (required for parameter change)
aws rds reboot-db-instance \
  --db-instance-identifier encrypted-mysql-db

⏱️ Wait 2-3 minutes for reboot

# Now try to connect WITHOUT SSL:
mysql -h $ENDPOINT -u admin -p

# Should fail: "SSL connection required" ❌

# Connect WITH SSL works:
mysql -h $ENDPOINT -u admin -p --ssl-ca=global-bundle.pem

✅ SSL enforced!
```

```
Automated Backups:
```

# **LAB 33: RDS IAM DATABASE AUTHENTICATION**

## **What is IAM Database Authentication?**

```
Traditional:
├─ Connect with username/password
├─ Password stored in application
└─ Security risk if hardcoded

IAM Authentication:
├─ No password needed!
├─ Uses IAM credentials
├─ Temporary token (15 minutes)
└─ More secure, auditable
```

---

## **Lab 33.1: Enable IAM Authentication**

```
RDS Console → encrypted-mysql-db → Modify

Database authentication:
└─ ✅ Enable IAM DB authentication

Continue → Apply immediately → Modify

⏱️ Wait 2-3 minutes
```

---

## **Lab 33.2: Create IAM User for Database Access**

```bash
# Create database user (from MySQL client)
mysql -h $ENDPOINT -u admin -p --ssl-ca=global-bundle.pem

# Create user with IAM authentication
mysql> CREATE USER 'iamuser' IDENTIFIED WITH AWSAuthenticationPlugin AS 'RDS';
mysql> GRANT ALL PRIVILEGES ON testdb.* TO 'iamuser'@'%';
mysql> FLUSH PRIVILEGES;
mysql> EXIT;
```

---

## **Lab 33.3: Create IAM Policy for Database Access**

```bash
# Create IAM policy
cat > rds-iam-auth-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "rds-db:connect",
      "Resource": "arn:aws:rds-db:us-east-1:ACCOUNT_ID:dbuser:DB-RESOURCE-ID/iamuser"
    }
  ]
}
EOF

# Get DB resource ID
DB_RESOURCE_ID=$(aws rds describe-db-instances \
  --db-instance-identifier encrypted-mysql-db \
  --query 'DBInstances[0].DbiResourceId' \
  --output text)

echo "DB Resource ID: $DB_RESOURCE_ID"

# Update policy with actual values
# Then create it:
aws iam create-policy \
  --policy-name RDSIAMAuth \
  --policy-document file://rds-iam-auth-policy.json

# Attach to your IAM user
aws iam attach-user-policy \
  --user-name YOUR_IAM_USER \
  --policy-arn arn:aws:iam::ACCOUNT_ID:policy/RDSIAMAuth
```

---

## **Lab 33.4: Connect Using IAM Authentication**

```bash
# Generate authentication token
TOKEN=$(aws rds generate-db-auth-token \
  --hostname $ENDPOINT \
  --port 3306 \
  --username iamuser \
  --region us-east-1)

echo "Token: $TOKEN"

# Connect using token as password
mysql -h $ENDPOINT \
  --user=iamuser \
  --password="$TOKEN" \
  --ssl-ca=global-bundle.pem \
  --enable-cleartext-plugin

✅ Connected with IAM authentication!
(No hardcoded password needed!)
```

# **LAB 35: DynamoDB ENCRYPTION IN TRANSIT**

## **How It Works:**

```
DynamoDB API:
├─ ALL connections use HTTPS
├─ TLS 1.2+ required
├─ Cannot disable encryption in transit
└─ Automatic, no configuration needed

✅ Always encrypted in transit!
```

---

## **Lab 35.1: Verify HTTPS Enforcement**

```bash
# Try HTTP (should fail)
curl http://dynamodb.us-east-1.amazonaws.com/

# Output: Connection refused or redirect to HTTPS

# HTTPS works:
curl https://dynamodb.us-east-1.amazonaws.com/

✅ Only HTTPS allowed!
```

---

## **Lab 35.2: VPC Endpoint for DynamoDB (Extra Security)**

**Why:** Keep DynamoDB traffic within AWS network (doesn't go over internet)

```bash
# Create VPC endpoint for DynamoDB
aws ec2 create-vpc-endpoint \
  --vpc-id vpc-XXXXXXXX \
  --service-name com.amazonaws.us-east-1.dynamodb \
  --route-table-ids rtb-XXXXXXXX

# Now DynamoDB traffic stays within AWS network
# Even more secure than internet HTTPS!

✅ VPC endpoint created!
```
