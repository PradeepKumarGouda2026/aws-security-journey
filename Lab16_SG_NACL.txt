# **LAB 78: SECURITY GROUP ADVANCED PATTERNS**

## **Lab 78.1: Create Test VPC (Simple Architecture)**

```bash
# CloudShell

echo "=== Creating Test VPC for SG/NACL Labs ==="

# Create VPC
TEST_VPC=$(aws ec2 create-vpc --cidr-block 10.1.0.0/16 --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=Test-VPC}]' --query 'Vpc.VpcId' --output text)

aws ec2 modify-vpc-attribute --vpc-id $TEST_VPC --enable-dns-hostnames

echo "Test VPC created: $TEST_VPC"

# Create 2 subnets
TEST_PUBLIC=$(aws ec2 create-subnet --vpc-id $TEST_VPC --cidr-block 10.1.1.0/24 --availability-zone us-east-1a --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Test-Public}]' --query 'Subnet.SubnetId' --output text)

TEST_PRIVATE=$(aws ec2 create-subnet --vpc-id $TEST_VPC --cidr-block 10.1.2.0/24 --availability-zone us-east-1a --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Test-Private}]' --query 'Subnet.SubnetId' --output text)

aws ec2 modify-subnet-attribute --subnet-id $TEST_PUBLIC --map-public-ip-on-launch

echo "Subnets created:"
echo "  Public: $TEST_PUBLIC"
echo "  Private: $TEST_PRIVATE"

# Create and attach IGW
TEST_IGW=$(aws ec2 create-internet-gateway --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=Test-IGW}]' --query 'InternetGateway.InternetGatewayId' --output text)

aws ec2 attach-internet-gateway --internet-gateway-id $TEST_IGW --vpc-id $TEST_VPC

echo "Internet Gateway attached: $TEST_IGW"

# Create route table for public subnet
TEST_RT=$(aws ec2 create-route-table --vpc-id $TEST_VPC --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=Test-Public-RT}]' --query 'RouteTable.RouteTableId' --output text)

aws ec2 create-route --route-table-id $TEST_RT --destination-cidr-block 0.0.0.0/0 --gateway-id $TEST_IGW

aws ec2 associate-route-table --route-table-id $TEST_RT --subnet-id $TEST_PUBLIC

echo "Route table configured: $TEST_RT"
echo "✅ Test VPC ready for experiments!"
```

## **Lab 78.2: Pattern - Security Group Chaining**

```bash
# CloudShell

echo "=== Creating Security Group Chain ==="

# Web Tier Security Group
WEB_SG=$(aws ec2 create-security-group --group-name web-tier --description "Web tier security group" --vpc-id $TEST_VPC --tag-specifications 'ResourceType=security-group,Tags=[{Key=Name,Value=Web-Tier-SG}]' --query 'GroupId' --output text)

echo "Web SG created: $WEB_SG"

# Allow HTTP from internet
aws ec2 authorize-security-group-ingress --group-id $WEB_SG --protocol tcp --port 80 --cidr 0.0.0.0/0

# Allow HTTPS from internet
aws ec2 authorize-security-group-ingress --group-id $WEB_SG --protocol tcp --port 443 --cidr 0.0.0.0/0

echo "✅ Web tier: Allows HTTP/HTTPS from internet"

# App Tier Security Group
APP_SG=$(aws ec2 create-security-group --group-name app-tier --description "App tier security group" --vpc-id $TEST_VPC --tag-specifications 'ResourceType=security-group,Tags=[{Key=Name,Value=App-Tier-SG}]' --query 'GroupId' --output text)

echo "App SG created: $APP_SG"

# Allow port 8080 ONLY from Web tier (security group reference!)
aws ec2 authorize-security-group-ingress --group-id $APP_SG --protocol tcp --port 8080 --source-group $WEB_SG

echo "✅ App tier: Allows 8080 ONLY from Web tier"

# Database Tier Security Group
DB_SG=$(aws ec2 create-security-group --group-name db-tier --description "Database tier security group" --vpc-id $TEST_VPC --tag-specifications 'ResourceType=security-group,Tags=[{Key=Name,Value=DB-Tier-SG}]' --query 'GroupId' --output text)

echo "DB SG created: $DB_SG"

# Allow MySQL ONLY from App tier
aws ec2 authorize-security-group-ingress --group-id $DB_SG --protocol tcp --port 3306 --source-group $APP_SG

# Allow PostgreSQL ONLY from App tier
aws ec2 authorize-security-group-ingress --group-id $DB_SG --protocol tcp --port 5432 --source-group $APP_SG

echo "✅ DB tier: Allows 3306/5432 ONLY from App tier"

echo ""
echo "=== Security Group Chain Complete! ==="
echo "Internet → Web (80/443) → App (8080) → DB (3306/5432)"
echo ""
echo "Security Group IDs:"
echo "  Web: $WEB_SG"
echo "  App: $APP_SG"
echo "  DB: $DB_SG"
```

## **Lab 78.5: View Security Group Rules**

```bash
# CloudShell

echo "=== Viewing Security Group Configurations ==="

# Function to describe SG nicely
describe_sg() {
    SG_ID=$1
    SG_NAME=$2
    
    echo ""
    echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
    echo "Security Group: $SG_NAME ($SG_ID)"
    echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
    
    echo "INBOUND RULES:"
    aws ec2 describe-security-groups --group-ids $SG_ID --query 'SecurityGroups[0].IpPermissions[*].[IpProtocol,FromPort,ToPort,IpRanges[0].CidrIp,UserIdGroupPairs[0].GroupId]' --output table
    
    echo ""
    echo "OUTBOUND RULES:"
    aws ec2 describe-security-groups --group-ids $SG_ID --query 'SecurityGroups[0].IpPermissionsEgress[*].[IpProtocol,FromPort,ToPort,IpRanges[0].CidrIp,UserIdGroupPairs[0].GroupId]' --output table
}

# Show all security groups
describe_sg $WEB_SG "Web-Tier"
describe_sg $APP_SG "App-Tier"
describe_sg $DB_SG "Database-Tier"
describe_sg $CLUSTER_SG "Cluster"
describe_sg $BASTION_SG "Bastion"
describe_sg $PRIVATE_SG "Private"

echo ""
echo "✅ All security groups configured!"
```

# **LAB 79: NETWORK ACL ADVANCED PATTERNS**

## **Lab 79.1: Create Restrictive Public Subnet NACL**

```bash
# CloudShell

echo "=== Creating Custom NACLs ==="

# Create NACL for public subnet
PUBLIC_NACL=$(aws ec2 create-network-acl --vpc-id $TEST_VPC --tag-specifications 'ResourceType=network-acl,Tags=[{Key=Name,Value=Public-NACL}]' --query 'NetworkAcl.NetworkAclId' --output text)

echo "Public NACL created: $PUBLIC_NACL"

# ===== INBOUND RULES =====

# Rule 10: DENY known malicious IP
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 10 --protocol -1 --cidr-block 198.51.100.0/24 --rule-action deny --ingress

echo "  Rule 10: DENY 198.51.100.0/24 (malicious IP range)"

# Rule 20: DENY another bad range
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 20 --protocol -1 --cidr-block 203.0.113.0/24 --rule-action deny --ingress

echo "  Rule 20: DENY 203.0.113.0/24 (another bad range)"

# Rule 100: Allow HTTP
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 100 --protocol tcp --port-range From=80,To=80 --cidr-block 0.0.0.0/0 --rule-action allow --ingress

echo "  Rule 100: ALLOW HTTP (80)"

# Rule 110: Allow HTTPS
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 110 --protocol tcp --port-range From=443,To=443 --cidr-block 0.0.0.0/0 --rule-action allow --ingress

echo "  Rule 110: ALLOW HTTPS (443)"

# Rule 120: Allow SSH from office IP only
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 120 --protocol tcp --port-range From=22,To=22 --cidr-block $MY_IP/32 --rule-action allow --ingress

echo "  Rule 120: ALLOW SSH from $MY_IP"

# Rule 130: Allow ephemeral ports (return traffic)
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 130 --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --ingress

echo "  Rule 130: ALLOW ephemeral ports (return traffic)"

# Rule 140: Allow from private subnet
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 140 --protocol -1 --cidr-block 10.1.0.0/16 --rule-action allow --ingress

echo "  Rule 140: ALLOW from VPC"

# ===== OUTBOUND RULES =====

# Rule 100: Allow HTTP
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 100 --protocol tcp --port-range From=80,To=80 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 110: Allow HTTPS
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 110 --protocol tcp --port-range From=443,To=443 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 120: Allow ephemeral ports (return traffic)
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 120 --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 130: Allow to VPC
aws ec2 create-network-acl-entry --network-acl-id $PUBLIC_NACL --rule-number 130 --protocol -1 --cidr-block 10.1.0.0/16 --rule-action allow --egress

echo "  Outbound rules configured"

# Associate with public subnet
PUBLIC_ASSOC=$(aws ec2 describe-network-acls --filters "Name=association.subnet-id,Values=$TEST_PUBLIC" --query 'NetworkAcls[0].Associations[0].NetworkAclAssociationId' --output text)

aws ec2 replace-network-acl-association --association-id $PUBLIC_ASSOC --network-acl-id $PUBLIC_NACL

echo "✅ Public NACL associated with public subnet"
```

## **Lab 79.2: Create Isolated Private Subnet NACL**

```bash
# CloudShell

echo "=== Creating Private Subnet NACL ==="

# Create NACL for private subnet
PRIVATE_NACL=$(aws ec2 create-network-acl --vpc-id $TEST_VPC --tag-specifications 'ResourceType=network-acl,Tags=[{Key=Name,Value=Private-NACL}]' --query 'NetworkAcl.NetworkAclId' --output text)

echo "Private NACL created: $PRIVATE_NACL"

# ===== INBOUND RULES =====

# Rule 100: Allow from VPC only
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 100 --protocol -1 --cidr-block 10.1.0.0/16 --rule-action allow --ingress

echo "  Rule 100: ALLOW from VPC (10.1.0.0/16)"

# Rule 110: Allow ephemeral ports from internet (for outbound-initiated connections)
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 110 --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --ingress

echo "  Rule 110: ALLOW ephemeral ports (return traffic)"

# Rule 200: DENY all inbound from internet (explicit)
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 200 --protocol -1 --cidr-block 0.0.0.0/0 --rule-action deny --ingress

echo "  Rule 200: DENY all from internet (explicit)"

# ===== OUTBOUND RULES =====

# Rule 100: Allow to VPC
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 100 --protocol -1 --cidr-block 10.1.0.0/16 --rule-action allow --egress

# Rule 110: Allow HTTP for updates
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 110 --protocol tcp --port-range From=80,To=80 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 120: Allow HTTPS for updates
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 120 --protocol tcp --port-range From=443,To=443 --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Rule 130: Allow ephemeral ports
aws ec2 create-network-acl-entry --network-acl-id $PRIVATE_NACL --rule-number 130 --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --egress

echo "  Outbound rules configured"

# Associate with private subnet
PRIVATE_ASSOC=$(aws ec2 describe-network-acls --filters "Name=association.subnet-id,Values=$TEST_PRIVATE" --query 'NetworkAcls[0].Associations[0].NetworkAclAssociationId' --output text)

aws ec2 replace-network-acl-association --association-id $PRIVATE_ASSOC --network-acl-id $PRIVATE_NACL

echo "✅ Private NACL associated with private subnet"
echo ""
echo "Private subnet can:"
echo "  ✅ Communicate within VPC"
echo "  ✅ Initiate connections to internet (for updates)"
echo "  ❌ Receive connections from internet"
```

## **Lab 79.3: View NACL Rules**

```bash
# CloudShell

echo "=== Viewing NACL Configurations ==="

# Function to describe NACL
describe_nacl() {
    NACL_ID=$1
    NACL_NAME=$2
    
    echo ""
    echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
    echo "Network ACL: $NACL_NAME ($NACL_ID)"
    echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
    
    echo "INBOUND RULES (processed in order):"
    aws ec2 describe-network-acls --network-acl-ids $NACL_ID --query 'NetworkAcls[0].Entries[?Egress==`false`].[RuleNumber,Protocol,RuleAction,CidrBlock,PortRange.From,PortRange.To]' --output table
    
    echo ""
    echo "OUTBOUND RULES (processed in order):"
    aws ec2 describe-network-acls --network-acl-ids $NACL_ID --query 'NetworkAcls[0].Entries[?Egress==`true`].[RuleNumber,Protocol,RuleAction,CidrBlock,PortRange.From,PortRange.To]' --output table
}

describe_nacl $PUBLIC_NACL "Public-NACL"
describe_nacl $PRIVATE_NACL "Private-NACL"

echo ""
echo "✅ NACL configurations complete!"
```

## **Lab 80.4: Troubleshooting Scenarios**

```bash
# CloudShell

echo "=== Common Troubleshooting Scenarios ==="

cat << 'EOF'

SCENARIO 1: "I can't access my web server!"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Troubleshooting checklist:

1. ✅ Does instance have public IP?
   Command: aws ec2 describe-instances --instance-ids i-xxx
   Look for: PublicIpAddress field

2. ✅ Is Security Group allowing port 80?
   Command: aws ec2 describe-security-groups --group-ids sg-xxx
   Look for: Inbound rule allowing port 80

3. ✅ Is NACL allowing port 80 inbound?
   Command: aws ec2 describe-network-acls --network-acl-ids nacl-xxx
   Look for: Inbound rule with port 80, action=allow

4. ✅ Is NACL allowing ephemeral ports outbound?
   Look for: Outbound rule allowing ports 1024-65535

5. ✅ Is route table configured?
   Command: aws ec2 describe-route-tables --route-table-ids rtb-xxx
   Look for: Route to 0.0.0.0/0 via Internet Gateway

6. ✅ Is Internet Gateway attached?
   Command: aws ec2 describe-internet-gateways --internet-gateway-ids igw-xxx
   Look for: State=attached

7. ✅ Is web service actually running?
   SSH to instance: systemctl status httpd

Common causes:
├─ Security group missing inbound rule (most common!)
├─ NACL missing ephemeral port rule
├─ No public IP assigned
├─ Route table missing IGW route
└─ Web service not running

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SCENARIO 2: "Web server can't reach internet!"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Troubleshooting checklist:

1. ✅ Is Security Group allowing outbound?
   Default: Yes (all outbound allowed)
   Check: aws ec2 describe-security-groups --group-ids sg-xxx
   Look for: IpPermissionsEgress

2. ✅ Is NACL allowing outbound?
   Command: aws ec2 describe-network-acls --network-acl-ids nacl-xxx
   Look for: Outbound rules allowing HTTP/HTTPS (80/443)

3. ✅ Is NACL allowing inbound ephemeral ports?
   Look for: Inbound rule allowing ports 1024-65535
   WHY: Return traffic from internet comes back on ephemeral ports!

4. ✅ Is there a route to internet?
   Public subnet: Route to IGW
   Private subnet: Route to NAT Gateway

Common causes:
├─ NACL missing ephemeral port inbound (most common!)
├─ NACL missing HTTP/HTTPS outbound
├─ No route to IGW/NAT Gateway
└─ NAT Gateway in wrong subnet

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SCENARIO 3: "App server can't talk to web server!"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Troubleshooting checklist:

1. ✅ Does web server SG allow traffic from app server SG?
   Command: aws ec2 describe-security-groups --group-ids <web-sg>
   Look for: Source security group = app-sg

2. ✅ Are both instances in same VPC?
   Command: aws ec2 describe-instances --instance-ids i-xxx
   Look for: VpcId field

3. ✅ Is NACL allowing traffic between subnets?
   Both NACLs should allow VPC CIDR (10.x.0.0/16)

4. ✅ Is route table configured for local traffic?
   Should have: 10.x.0.0/16 → local (automatic)

Common causes:
├─ Security group not allowing source SG
├─ NACL blocking inter-subnet traffic
├─ Wrong port number in SG rule
└─ Instances in different VPCs

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SCENARIO 4: "NACL changes not working!"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Remember:
├─ Rules processed in NUMBER order (lowest first)
├─ First ALLOW or DENY wins
├─ Rule * is implicit DENY at end

Example issue:
Rule 100: ALLOW 0.0.0.0/0 port 80
Rule 200: DENY 198.51.100.0/24 all

Problem: Rule 100 matches first, traffic allowed!
Solution: Move DENY to Rule 50 (before ALLOW)

Correct order:
Rule 50: DENY 198.51.100.0/24 all
Rule 100: ALLOW 0.0.0.0/0 port 80

Now DENY happens first! ✅

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

EOF

echo "Study these scenarios - they're common on the exam! 📚"
```

```bash
═════════════════════════════════════════════════════════
WHEN TO USE SECURITY GROUPS VS NACLs - DECISION TREE
═════════════════════════════════════════════════════════

START: I need to control network traffic
    |
    ├─ Q: Do I need to DENY specific IPs/ranges?
    │   └─ YES → Use NACL (SGs can't DENY)
    │
    ├─ Q: Is this instance-specific control?
    │   └─ YES → Use Security Group
    │
    ├─ Q: Is this subnet-level control?
    │   └─ YES → Use NACL
    │
    ├─ Q: Do I need stateful behavior (easy return traffic)?
    │   └─ YES → Use Security Group
    │
    ├─ Q: Do I want to reference other security groups?
    │   └─ YES → Use Security Group
    │
    ├─ Q: Do I need explicit rule ordering?
    │   └─ YES → Use NACL
    │
    └─ Q: Defense in depth (multiple layers)?
        └─ YES → Use BOTH! ✅

═════════════════════════════════════════════════════════

BEST PRACTICE: Always use BOTH!

Primary control: Security Groups (instance-level, easy)
Secondary control: NACLs (subnet-level, backup)

Example 3-tier app:
├─ Web tier: web-sg + public-nacl
├─ App tier: app-sg + private-nacl
└─ DB tier: db-sg + private-nacl

Each instance protected by 2 firewalls! 🛡️🛡️
```

## Traffic Flow Checklist

For traffic to flow successfully:

**Inbound (Internet → Instance):**
1. ✅ NACL Inbound: Allow destination port
2. ✅ Security Group Inbound: Allow destination port
3. ✅ Security Group Outbound: Auto-allowed (stateful)
4. ✅ NACL Outbound: Allow ephemeral ports (1024-65535)

**Outbound (Instance → Internet):**
1. ✅ Security Group Outbound: Allow destination port
2. ✅ NACL Outbound: Allow destination port
3. ✅ NACL Inbound: Allow ephemeral ports (1024-65535)
4. ✅ Security Group Inbound: Auto-allowed (stateful)

**Between Instances (same VPC):**
1. ✅ Source SG Outbound: Allow
2. ✅ Source NACL Outbound: Allow
3. ✅ Dest NACL Inbound: Allow
4. ✅ Dest SG Inbound: Allow
5. ✅ Return traffic: Reverse all above

## Common Issues & Solutions

| Issue | Most Common Cause | Solution |
|-------|------------------|----------|
| Can't reach web server | SG missing inbound rule | Add port 80/443 inbound |
| Server can't reach internet | NACL missing ephemeral inbound | Add 1024-65535 inbound |
| SSH timeout | No public IP or SG blocks SSH | Add public IP + port 22 rule |
| Intermittent connectivity | NACL rule order wrong | Check rule numbers |
| Can't ping instance | ICMP not allowed | Add ICMP rule to SG |

## Remember

- **Security Groups**: Stateful, instance-level, only ALLOW
- **NACLs**: Stateless, subnet-level, ALLOW + DENY
- **Both**: Required for defense in depth!
